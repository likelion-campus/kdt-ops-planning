## 1. 학습퀴즈 — 발행·운영 정책 (회의 §1 + v1.6 리네이밍)

> **메뉴명 (v1.6)**: LNB 메뉴 `AI 퀴즈` → **`학습퀴즈`**, 일일 자동 퀴즈 `오늘의 퀴즈` → **`학습퀴즈`** 로 통일한다. 학생 탭은 `학습퀴즈 / 오답노트 / 보충 퀴즈`. (AI가 문항을 생성하는 **`AI 퀴즈 생성`·`AI 문항 생성`** 액션 라벨은 생성 방식을 가리키므로 그대로 유지)

### 1.1 발행 시간 / 자동 1개 + 추가 발행

| 항목 | 내용 |
|---|---|
| **기본 발행** | **매일 08:30 자동 1개 발행** (휴일 제외, 다음 수업일에 진행) |
| **자동 생성 기준 (v1.6 신규)** | 자동 학습퀴즈는 **AI 노트가 있는 가장 최근 학습일의 모든 노트**를 출제 범위로 삼는다. 하루에 AI 노트가 여러 개 생성될 수 있으므로, **그날의 모든 노트를 합쳐** 문항을 구성한다. (특정 노트 1개가 아니라 마지막 노트 보유일 전체 기준) |
| **추가 발행 (v1.5 변경)** | 강사가 직접 작성한 객관식 퀴즈를 자동 발행과 별개로 추가 발행 가능. **생성일 기준 하루 최대 20개**(자동 1개 포함). 발행되면 학생뷰에 학습퀴즈 **블럭이 여러 개** 연속 노출(§1.5) |
| **안내** | 자동 알림 없이 매니저가 학생에게 현장 안내 (08:30 풀이 시작 ~ 09:30 강사 리뷰) |
| **생성 실패 (v1.5 신규)** | 자동 생성 실패는 **학생뷰에 노출하지 않는다(그날 퀴즈 미발행과 동일 처리)**. **매니저뷰에서만** 생성 실패를 표시하고, **즉시 재생성**(재생성 → 검토 → 발행) 동선을 제공한다 |
| **수정** | 발행 이후 텍스트(문제·보기·해설)만 수정 — 정답·보기 번호 잠금 |
| **수정 표시 (v1.1 신규)** | 발행 후 텍스트 수정 시 학생뷰에 **`수정됨 · YYYY-MM-DD HH:mm`** 배지 노출 (AI 노트 패턴과 동일 톤). 응시 완료 학생도 결과 화면에서 확인. 적용 대상 = 본문·보기·해설 |
| **단일 재발행 (v1.1 신규)** | 세트 1개 또는 문항 1개만 재발행 가능. (a) 자동 생성 오류 세트 → 그 세트만 재생성·재발행 (b) 발행 후 정답 오류 → 해당 문항만 정정·재발행. 재발행 시 **해당 응시 데이터 invalidation·재집계** (UI는 confirm 모달로 안내, 정답·보기 번호 잠금 유지). 백엔드 invalidation·재집계 상세는 PRD v1.3 명세 |

### 1.2 강사 진단 뷰 (09:30 리뷰 우선순위 판단용) — v1.5 3탭화

#### 1.2.3 발행본 상세·리스트 — 중도포기자 집계 규칙 (v1.12 신규)

> 프로젝트 매니저뷰 중도포기자 집계(§6.6, v1.11)와 **동일 철학**을 학습퀴즈 매니저뷰에 적용한다. 단 **기준 시점은 `퀴즈 생성 시점`**이다(프로젝트의 `등록 시점`에 대응). 퀴즈 응시 점수는 그 퀴즈를 만든 시점의 재적 명단을 기준으로 집계하는 것이 의도다.

| 항목 | 규칙 |
|---|---|
| **집계 대상(분모)** | 발행본 상세 3탭(결과 요약 KPI·학생별 점수·미응시 명단)과 `발행된 퀴즈` 리스트 행의 **응시율·평균·미응시 수**는 **그 퀴즈 생성일 기준 재적생**(중도포기자 제외)만 센다 |
| **생성 후 중도포기자 — 점수 보존** | 퀴즈 생성 시점에 재적이었던 학생은 이후 중도포기해도 **응시 점수를 보존**해 학생별 점수에 그대로 노출한다(`중도포기` 배지로만 식별, 흐림·잠금 없음) |
| **생성 전 중도포기자 — 제외** | 퀴즈 생성 시점에 **이미 중도포기 확정**인 학생은 **발행본 상세·리스트 집계에서 제외**한다. 분모·명단·미응시 어디에도 포함하지 않는다 |
| **안내·가이드** | 발행본 상세 상단에 **`퀴즈 생성 시점(YY.MM.DD) 기준 재적생`** 안내를 노출하고, **중도포기자 현황은 출결현황에서 확인**하도록 가이드한다 |
| **적용 범위** | 본 규칙은 **발행본 상세 3탭 + 발행 퀴즈 리스트**에만 적용한다. **보충 퀴즈 사용현황 히트맵**은 특정 퀴즈 시점이 없는 누적(학생×날짜) 뷰이므로 **본 규칙에서 제외**하고 기존 표시를 유지한다 |

데이터: 중도포기 학생에 **확정일(`droppedAt`)**을 둔다(미지정 시 전 기간 중도포기로 간주). 집계는 헬퍼 **`isDroppedAsOf(student, 퀴즈생성일)`**로 판정한다(프로토타입 `components.js`).

#### 1.2.1 소요시간 — 매니저뷰 진단 전용 (v1.9 개정, 구 평균 응시시간·목표 응시시간)

> **학생뷰 소요시간 전면 제거 (v1.9)**: 학생뷰에는 소요시간을 **일절 표시하지 않는다** — 응시 중·결과 화면·과거 풀이 내역 리스트·보충퀴즈 전용 결과뷰 모두 비표시. *(v1.8의 "결과 화면 = 종합+문항별 본인 소요시간 표시" 결정을 번복)*. 소요시간 집계·표시는 아래 **매니저뷰 진단 용도로만** 유지한다. 목표 15분 표기는 v1.8에서 이미 제거.

| 항목 | 내용 |
|---|---|
| **문항별 평균 소요시간** | 문항마다 **평균 소요시간**을 집계해 표시 — **문제 난이도 측정 지표**(`쉬움/보통/어려움`). 매니저는 소요시간·오답률이 모두 높은 문항을 09:30 리뷰 우선순위로 판단 |
| **학생별 소요시간** | 학생별 **총 풀이 시간**을 발행본 `학생별 점수`·개별 드릴다운에 표시. 드릴다운의 문항별 시간은 **해당 학생의 실제 소요시간**(평균 아님) |
| **표시 위치 (매니저뷰만)** | 매니저 결과 요약(**KPI 4종 + 문항별 평균 소요시간·난이도 태그**), 매니저 학생별 점수(`⏱ 소요시간` 컬럼 = 본인 실제 총 시간), 매니저 개별 드릴다운(총 시간 + 문항별 본인 실제 시간). **학생뷰에는 미노출**(v1.9) |

#### 1.2.2 발행본 `퀴즈 풀이` — 수업용 함께 풀기 (v1.10 신규)

> 강사가 **수업 중 학생들과 함께** 발행본 퀴즈를 풀어보며 정답·해설을 즉시 설명하는 진행 도구다. 발행본 상세 상단 액션은 **`퀴즈 수정` · `퀴즈 풀이` · `추가 퀴즈 생성`** 3종이며, `퀴즈 풀이`는 `퀴즈 수정` 옆에 둔다(스크린샷 시안 기준).

| 항목 | 내용 |
|---|---|
| **진입** | 매니저뷰 `발행된 퀴즈` → 발행본 상세 상단 **`퀴즈 풀이`**. 학생뷰에는 없는 **매니저뷰 전용** 동선 |
| **진행 방식** | 학생 응시와 **UI는 동일**(한 화면 한 문항·보기 선택)하되, 보기를 고르고 **`정답 확인`을 누르면 그 문항의 정답·해설을 즉시 공개**(선택 보기 정답/오답 하이라이트) → `다음 문항` → 마지막은 `퀴즈 풀이 마치기`. *(학생 응시는 10문항 모두 풀고 마지막에 일괄 채점하지만, 퀴즈 풀이는 매 문항마다 즉시 정답 공개)* |
| **데이터 영향** | **채점·집계·오답노트 누적 없음**. 강의 진행용이므로 학생 응시 결과·발행본 KPI/통계에 **전혀 반영하지 않는다** |
| **대상 문항** | 발행본 전체 문항(`set.questions`). 정답·보기는 발행본 그대로(잠금 상태와 무관, 읽기 전용 진행) |

### 1.3 발행 시간 수정·즉시 발행 (매니저 UI)

- 매니저 `퀴즈 발행하기` 탭 슬롯에 **발행 예정 시간 표시 + 수정 + 즉시 발행**
- 수정 → 예약 발행 일시 입력(시각 input + 휴일 처리 안내) → 저장 시 적용

### 1.4 매니저 '퀴즈 발행하기' 흐름 (v1.2 신규 — 메뉴명 변경)

> 메뉴명 **`오늘의 Draft` → `퀴즈 발행하기`** 로 변경.

> **단위 체계**: **퀴즈**(발행 단위 = 슬롯 1개) > **문항**(1개 = `문제` + `객관식 보기` + `정답` + `해설`). 퀴즈 전체 생성은 **`AI 퀴즈 생성`**, 단일 문항 생성은 **`AI 문항 생성`** 으로 구분한다.

#### 1.4.1 AI 퀴즈 생성 (퀴즈 전체 · overwrite)

- 퀴즈 전체 문항을 **AI로 새로 생성**(이미 작성된 문항은 **덮어쓰기** — 경고 노출)
- 모드: **(a) AI 노트 기반** — AI 노트를 체크박스로 복수 선택 → 해당 노트 기반 생성 / **(b) 입력 기반** — 개념·주제 텍스트 입력 → 관련 문항 생성. **입력 기반에는 예시 프롬프트 안내**(클릭 시 입력란에 채워지는 예시 문구 + "구체적으로 적을수록 품질↑" 가이드)를 함께 노출 (v1.5)
- **생성할 문항 수** 지정(5/10/15 — 1세트 최대 15문항)
- 발행본에 적용 시 응시 결과 재집계 + 학생뷰 수정됨 배지

#### 1.4.2 문항별 AI 문항 생성 (단일 · overwrite)

- 문항마다 **`AI 문항 생성`** — 개념·주제 텍스트 입력 → 관련 **객관식 1문항(문제·보기·정답·해설)** 자동 생성하여 **해당 문항 덮어쓰기**
- 발행본이면 해당 문항 **응시 결과 무효화·재집계** + **수정됨 · 시각** 배지(정답·보기 번호 잠금)

> **의견 결정(2026-05-29)**: 추가 세트의 자동발행 시각은 **날짜+시각 자유 입력(datetime) + 즉시 발행** 으로 제공하되, "오전 퀴즈 슬롯(08:30~09:30) 권장" 가이드를 함께 노출해 학생 알림 분산을 줄인다. 시스템 데일리 1세트는 08:30 기준(매니저 조정 가능).

## 6. 프로젝트 — 학생뷰 3탭(+제출 버튼) / 매니저뷰 2탭

### 6.0 태그 체계 (v1.3 — 단계 정의) ⭐

> 프로젝트는 **두 개의 독립 축**으로 표현한다: ① *프로젝트 자체*의 생명주기(**전체 단계**), ② *학생 본인 기준*의 진행(**내 진행 상태**). 여기에 **종류(회차)** 분류와 제출본 단위 **비공개·우수** 배지가 직교한다. 뷰에 따라 주(主) 배지가 다르다.

**① 종류(회차) 태그** — 분류용, 4종: `기초` / `심화` / `파이널` / `기타` (색상 구분). 학생·매니저 공통, 카드·상세 상단.

**② 전체 단계 (시스템, 날짜로 자동 전환)** — 제출 기간 `[제출시작, 제출마감]` + 피드백 기간 `[, 피드백마감]` 기준:

| key | 라벨 (v1.5) | 전환 조건 | 의미 |
|---|---|---|---|
| `scheduled` | 예정 | now < 제출시작 | 카드 생성됨, 제출 오픈 전 |
| `submitting` | **제출 마감 D-N** | 제출시작 ≤ now ≤ 제출마감 | 학생 제출·수정 가능 (라벨 `제출 마감` + 마감 D-day) |
| `feedback` | **피드백 진행중** | 제출마감 < now ≤ 피드백마감 | 제출 잠금, 매니저 피드백 작성 |
| `closed` | 종료 | now > 피드백마감 | 활동 종료, 열람만 |

> 제출마감~피드백시작 공백은 `피드백 진행`에 흡수(매니저 채점 준비 포함).

**③ 내 진행 상태 (학생 본인, 제출축 전용)** — *학생뷰 주 배지*. (v1.5: **피드백 도착은 상태값에서 분리** → 제출 완료 상태에 별도 메시지 아이콘으로 표기)

| key | 라벨 | 조건 | 다음 행동 (CTA) |
|---|---|---|---|
| `not_submitted` | 미제출 | 제출 진행 중 · 본인 제출 없음 | `제출하기` |
| `draft` | 임시저장 | 임시저장만 함(미제출) | **`제출하기` 유지** — 클릭 시 임시저장 내용 로드해 이어서 작성 (라벨을 `이어서 작성`으로 바꾸지 않음, v1.5 결정) |
| `submitted` | 제출 완료 | 제출함 | 게시판 열람 (피드백 도착 시 **별도 메시지 아이콘** 부가) |
| `missed` | 미제출 마감 | 종료까지 미제출 | 열람만 |
| `not_open` | 오픈 예정 | 예정 단계 · 미제출 | 대기 |

> **피드백 도착 표시(v1.5)**: 별도 상태값(`feedback_ready`)을 두지 않고, 제출 완료 카드/상세에 **메시지 아이콘 배지(`피드백`)** 로 도착 여부만 표기한다. 수정 가능 여부에는 영향을 주지 않는다(§6.2).

**④ 제출본 단위 배지 (단계와 직교)** — `우수`(매니저 마크), `외부 공개 제한`(매니저 모더레이션, §6.3), `공개 중`(학생 외부 공개). 제출본 카드에만 노출.

**표시 위치 — 뷰별 표현 분리**

| 요소 | 학생뷰 | 매니저뷰 |
|---|---|---|
| 종류(회차) | 카드·상세 상단 | 카드·상세 상단 |
| 전체 단계(②) | **보조**(작게, 예: `제출 진행 D-3`) | **주 배지** + 제출률·피드백 필요 건수 |
| 내 진행 상태(③) | **주 배지**(카드 우측·상세 상단) | — |
| 제출본 배지(④) | 본인 제출본 안내(`외부 공개 제한됨` + 사유 등) | 제출현황·피드백 보드 카드 |

### 6.1 학생뷰 카드 표시 (정보 간소화)

| 항목 | 내용 |
|---|---|
| **종류 태그** | `기초` / `심화` / `파이널` / `기타` (좌측) |
| **전체 단계(보조)** | 예정/제출 마감 D-N/피드백 진행중/종료 — 작게, D-day 부가 |
| **내 진행 상태(주)** | 미제출/임시저장/제출 완료/미제출 마감 — 카드 우측에 강조. **피드백 도착은 별도 메시지 아이콘**으로 부가(상태값 아님) |
| **표시 정보** | 제목 + 제출 기간 + 피드백 기간 (나머지 상세는 회차 내부) |

### 6.2 학생뷰 상세 — 3탭 + 제출 버튼 (v1.3 변경)

> **`제출하기`는 탭이 아니라 버튼**이다. **문제 설명 좌측**에 눈에 띄게 배치하고, 상태에 따라 라벨·활성이 바뀌어 단계를 한눈에 보여준다.

탭(3): **문제** / **제출 프로젝트 리스트** / **받은 피드백**

**제출 버튼 (문제 탭 좌측 CTA)**

| 전체 단계 | 본인 상태 | 버튼 | 활성 |
|---|---|---|---|
| 제출 진행(제출 마감) | 미제출 | **`제출하기`** | 활성 |
| 제출 진행(제출 마감) | 임시저장 | **`제출하기`** (클릭 시 **임시저장 내용 로드**해 이어 작성, 라벨 유지) | 활성 |
| 제출 진행(제출 마감) | 제출 완료 | **`수정하기`** | 활성 |
| 예정 | — | `제출 오픈 예정` | 비활성 |
| 피드백 진행중/종료 | 제출함 | `제출 완료 (수정 마감)` | 비활성 |
| 피드백 진행중/종료 | 미제출 | `제출 기간 종료` | 비활성 |

> **수정 가능 여부는 제출 기간으로만 결정한다 (v1.5 결정 2).** 제출 기간 중이면 **피드백 도착 여부와 무관하게 수정 가능**하며, 제출 마감 이후에는 피드백 유무와 무관하게 수정 불가. (제출 기간과 피드백 기간이 통상 겹치지 않고, 겹치더라도 마이너 수정으로 가정 — 단순 정책 우선)

- 버튼 옆/아래에 **내 진행 상태 + 마감 D-day** 보조 노출 → 기간이 지나면 버튼이 **자동 비활성**되어 단계를 즉시 인지.
- 버튼 클릭(활성 시) → 제출/수정 폼(fullpage) 진입.
- 탭별: **문제**(설명 + 좌측 제출 CTA) / **제출 프로젝트 리스트**(제출 기간 종료=피드백 기간부터 전체 공개, 본인 맨 앞) / **받은 피드백**(본인만).

> **제출본 공개 시점 (v1.6 변경)**: 기존 정책은 "**학생 본인이 제출한 이후**부터 다른 학생 제출본 열람"이었으나, **"제출 기간이 끝난 뒤(= 피드백 기간부터) 전체 공개"** 로 변경한다. 즉 **제출 기간 중에는 문제만 표시**(다른 학생 제출본 비공개), **피드백 기간 진입 시 제출 여부와 무관하게 모든 제출본이 공개**되고 이때부터 **수정 불가**(§6.2 수정 가능=제출 기간만 정책과 정합). 최초 진입 시 기본 노출은 `문제` 탭. (베끼기 방지 + 마감 후 일괄 공개 의도)

> **제출 프로젝트 리스트 정렬·페이지네이션 (v1.10 신규)**: 공개된 제출 프로젝트 리스트는 **본인 제출본을 1페이지 맨 앞에 고정**한다(`내 제출본` 배지 + 아웃라인 강조). 본인 제출본은 **페이지네이션 대상에서 제외**하므로 **2페이지부터는 본인 제출본이 보이지 않는다** — 다른 학생 제출본만 **페이지당 N건**(프로토타입 9건)으로 나눠 `이전/다음`으로 탐색한다. 헤더에 총 건수를 표기하고, 1페이지에서만 "내 프로젝트가 가장 먼저 보여요" 안내를 노출한다.

### 6.3 외부 공개 / 외부 공개 제한 (v1.5 — 모델 정리)

> **코호트(수업) 내 공유는 항상 고정**이다(제출 시 클래스 게시판 공개). 여기서 켜고 끄는 것은 **"외부 공개"** = 로그인 없이 별도 주소로 해당 프로젝트만 열람하는 기능이다.

- **제출 폼의 `외부 발행` 토글 없음**(v1.1) — 외부 공개는 제출 후 **`제출 프로젝트 리스트` → 본인 제출본 → `외부 공유하기`** 다이얼로그에서만 처리
- 다이얼로그: **외부 공개 토글(ON/OFF)** + **링크 복사**. ON = 공개 링크 생성·열람 가능 / OFF = 링크 비활성화. **SNS 연동 없음**. 기본 OFF, 학생이 켜고 끌 수 있음
- **외부 공개 제한 (v1.5 신규)**: 매니저는 특정 제출물의 **외부 공개를 제한**할 수 있다.
  - 매니저가 **제한 사유를 필수 입력**하고 제한하면, 해당 제출물의 외부 공개는 OFF로 강제되고 학생은 외부 공개를 **켤 수 없다**.
  - 제한 사유는 **학생의 `외부 공유하기` 화면에 표시**되며, "매니저·강사에게 문의해 해제" 안내가 함께 노출된다.
  - **해제는 매니저만** 가능(사유 확인 후 해제).
  - 표기: 제출본 카드/상세에 `외부 공개 제한` 배지(④).
- **모더레이션 통합 (v1.5)**: 기존 "비공개 전환(코호트 게시판에서 제거)" 모더레이션은 **별도로 두지 않고 `외부 공개 제한`으로 통합**한다. 매니저 모더레이션 = 외부 공개 제한 하나로 단일화(코호트 내 게시판 공개는 항상 유지).

### 6.4 매니저뷰 카드 (정보 풀세트)

제목 + 제출 기간 + 피드백 기간 + 제출 훈련생(N명/전체 N명) + 제출 비율(%) + **전체 단계(주 배지)** + 종류 태그. (내 진행 상태는 매니저뷰 비노출)

> **전체 학생수 = 재적생(중도포기자 제외) (v1.11)**: 카드의 `전체 N명`·제출 비율 분모는 **중도포기자를 제외한 재적생** 기준이며, 분자(제출 N명)도 재적생 제출자만 센다. 전체 인원 옆에 **`중도포기자 제외`** 안내 텍스트를 함께 노출한다(§6.6).

### 6.5 매니저뷰 상세 — 2탭 (v1.3 변경 — 피드백 탭 폐지, 제출현황으로 통합)

- 상단 액션 **`프로젝트 정보 수정`** (구 `회차 수정`) — 클릭 시 **모달**로 등록 시 입력 항목 전체(회차 종류·회차명·한 줄 소개·문제 설명·제출/피드백 기간) 수정. **문제 설명 입력은 마크다운 에디터**(툴바 + 실시간 미리보기, 라벨은 `문제 설명` — `· 마크다운` 표기 제거, v1.5)
- **`프로젝트 삭제` (v1.9 신규)** — **전체 단계 `예정`(= 제출 시작 전, 발행 전)인 회차만** 상세 상단 액션으로 삭제 가능(확인 모달, `예정` 단계는 학생 제출 데이터 없음). **제출 시작(발행) 이후에는 삭제 불가 — 액션 자체를 노출하지 않는다**
- 상세 헤더는 리스트와 동일 우선순위: **제목 + 회차** → **전체 단계** → 제출/피드백 기간 + 제출률

탭(3, v1.4): **문제** / **제출현황** / **미제출명단**

**제출현황 탭 (피드백 통합)**
- **필터**: `전체` / `피드백 전` / `피드백 완료`
- 제출본 카드 **썸네일 위 태그**로 `피드백 완료`/`피드백 전` 표시 + **우수 ★ 썸네일 오버레이** + `공개 중` 배지
- 카드 클릭 → 제출본 상세(내용) + **하단에서 피드백 등록·수정**, `우수 마크` / **`외부 공개 제한` / `외부 공개 제한 해제`**(사유 입력형 — v1.5에서 `공개 설정` 대체, §6.3). 제출본 카드/헤더에 `외부 공개 제한`·`공개 중` 배지 반영
- 피드백 작성은 제출현황 안에서 진행. 피드백 기간과 무관하게 작성 가능(기간 태그 제거)

**미제출명단 탭 (v1.4 신규)**
- 제출하지 않은 학생 리스트만 표시(번호·이름·`미제출` 태그). 탭 라벨에 미제출 인원 수. 전원 제출 시 빈 상태 안내
- **미제출 = 재적생 중 미제출만 (v1.11)**: 미제출명단·탭의 미제출 인원 수는 **중도포기자를 제외한 재적생 중 미제출자**만 센다. 중도포기자는 미제출명단에 포함하지 않는다(과거 정책은 미제출+중도포기 혼재 → 분리)(§6.6).

### 6.6 중도포기자 집계·제출본 보존 규칙 (v1.11 신규)

> 매니저뷰의 모든 인원 통계는 **중도포기자(admin 지정)를 제외한 재적생**을 기준으로 한다. 단 **이미 제출한 프로젝트는 중도포기 여부와 무관하게 보존**한다.

| 항목 | 규칙 |
|---|---|
| **전체 학생수(분모)** | **재적생 = 전체 − 중도포기자**. 카드·상세 헤더에 `전체 N명` 옆 **`중도포기자 제외`** 안내 텍스트 노출 |
| **제출 수(분자)·제출률** | **재적생 중 제출자**만 분자로 집계(`재적 제출자 / 재적생`). 중도포기자 제출본은 분자에서 제외 |
| **미제출명단·미제출 수** | **재적생 중 미제출자만**. 중도포기자는 미제출로 세지 않는다(미제출명단에서 제외) |
| **제출현황 탭(제출본 그리드)** | **모든 제출본을 보존·표시**한다 — 중도포기자가 낸 제출본도 **삭제·비활성화하지 않고** 그대로 노출(`중도포기` 배지로만 식별, 흐림/잠금 없음). 탭의 `(N)` 건수는 표시되는 제출본 총수(중도포기 제출본 포함) |
| **시각 처리** | 중도포기자 제출본은 동등하게 표시하고 **`중도포기` 배지**만 부가. 명단·테이블에서 동명이인 표기(`이름 (전화 뒷자리4)`)는 중도포기 확정 시 `이름 (중도포기)`로 대체(매니저 전용, §7) |
