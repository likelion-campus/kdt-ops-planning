## 1. AI 퀴즈 — 발행·운영 정책 (회의 §1 + 추가 수정)

### 1.1 발행 시간 / 자동 1개 + 추가 발행

| 항목 | 내용 |
|---|---|
| **기본 발행** | **매일 08:30 자동 1개 발행** (휴일 제외, 다음 수업일에 진행) |
| **추가 발행** | 강사가 직접 작성한 객관식 퀴즈를 자동 발행과 별개로 추가 발행 가능 (수 무제한) |
| **안내** | 자동 알림 없이 매니저가 학생에게 현장 안내 (08:30 풀이 시작 ~ 09:30 강사 리뷰) |
| **수정** | 발행 이후 텍스트(문제·보기·해설)만 수정 — 정답·보기 번호 잠금 |
| **수정 표시 (v1.1 신규)** | 발행 후 텍스트 수정 시 학생뷰에 **`수정됨 · YYYY-MM-DD HH:mm`** 배지 노출 (AI 노트 패턴과 동일 톤). 응시 완료 학생도 결과 화면에서 확인. 적용 대상 = 본문·보기·해설 |
| **단일 재발행 (v1.1 신규)** | 세트 1개 또는 문항 1개만 재발행 가능. (a) 자동 생성 오류 세트 → 그 세트만 재생성·재발행 (b) 발행 후 정답 오류 → 해당 문항만 정정·재발행. 재발행 시 **해당 응시 데이터 invalidation·재집계** (UI는 confirm 모달로 안내, 정답·보기 번호 잠금 유지). 백엔드 invalidation·재집계 상세는 PRD v1.3 명세 |

### 1.2 강사 진단 뷰 (09:30 리뷰 우선순위 판단용)

매니저뷰 `발행된 퀴즈` 탭 → 각 발행본 클릭 시 다음 표시:
1. **응시 현황** — 학생별 응시 여부 + 정답 수 (n / 10)
2. **문항별 오답률** — 가장 많이 틀린 문항 식별
3. **보기 선택 분포** — 각 문항에서 보기별 응답 수 + 막대 그래프

### 1.3 발행 시간 수정·즉시 발행 (매니저 UI)

- 매니저 `퀴즈 발행하기` 탭 슬롯에 **발행 예정 시간 표시 + 수정 + 즉시 발행**
- 수정 → 예약 발행 일시 입력(시각 input + 휴일 처리 안내) → 저장 시 적용

### 1.4 매니저 '퀴즈 발행하기' 흐름 (v1.2 신규 — 메뉴명 변경)

> 메뉴명 **`오늘의 Draft` → `퀴즈 발행하기`** 로 변경.

> **단위 체계**: **퀴즈**(발행 단위 = 슬롯 1개) > **문항**(1개 = `문제` + `객관식 보기` + `정답` + `해설`). 퀴즈 전체 생성은 **`AI 퀴즈 생성`**, 단일 문항 생성은 **`AI 문항 생성`** 으로 구분한다.

| 항목 | 내용 |
|---|---|
| **슬롯 리스트** | 발행 대기 퀴즈를 **요약 행 리스트**로 표시(상태·예약 일시·이름·문항수). 행 클릭 시 편집/발행 폼 진입 |
| **상태 모델** | **임시저장**(제작 중, 예약·발행 전) / **예약발행**(일시 지정, 자동 발행 대기) / **발행됨** / **생성 실패** |
| **상단 고정 액션** | 편집 폼 상단에 **`AI 퀴즈 생성` · `임시저장` · `예약발행` · `즉시발행`** 고정 (신규 제작 시 동일 적용) |
| **예약발행 일시 노출** | **예약발행을 한 경우에만** 일시 표시(임시저장 상태에선 비노출). 변경 가능 |
| **발행 후 이동** | 즉시/예약 발행 시 **`발행된 퀴즈` 탭으로 이동**. 발행본도 같은 폼으로 재진입(수정·재발행) 가능 |
| **새 퀴즈 추가** | 클릭 시 빈 슬롯 1개 생성 → 곧바로 편집 폼이 열려 문항 제작 |
| **문항 추가** | 빈 문항 1개 추가(인라인 편집). 객관식 보기에 **1·2·3·4 번호 표기** |

#### 1.4.1 AI 퀴즈 생성 (퀴즈 전체 · overwrite)

- 퀴즈 전체 문항을 **AI로 새로 생성**(이미 작성된 문항은 **덮어쓰기** — 경고 노출)
- 모드: **(a) AI 노트 기반** — AI 노트를 체크박스로 복수 선택 → 해당 노트 기반 생성 / **(b) 입력 기반** — 개념·주제 텍스트 입력 → 관련 문항 생성
- **생성할 문항 수** 지정(5/10/15)
- 발행본에 적용 시 응시 결과 재집계 + 학생뷰 수정됨 배지

#### 1.4.2 문항별 AI 문항 생성 (단일 · overwrite)

- 문항마다 **`AI 문항 생성`** — 개념·주제 텍스트 입력 → 관련 **객관식 1문항(문제·보기·정답·해설)** 자동 생성하여 **해당 문항 덮어쓰기**
- 발행본이면 해당 문항 **응시 결과 무효화·재집계** + **수정됨 · 시각** 배지(정답·보기 번호 잠금)

> **의견 결정(2026-05-29)**: 추가 세트의 자동발행 시각은 **날짜+시각 자유 입력(datetime) + 즉시 발행** 으로 제공하되, "오전 퀴즈 슬롯(08:30~09:30) 권장" 가이드를 함께 노출해 학생 알림 분산을 줄인다. 시스템 데일리 1세트는 08:30 기준(매니저 조정 가능).

## 5. TIL — 작성 폼 우측 3탭 (재정의)

기존 (AI 노트 / 오답 / 실습) → 신규 **(AI 노트 / 퀴즈 결과 / 오답노트)**

| 탭 | 내용 |
|---|---|
| **AI 노트** | 오늘의 AI 노트 풀 마크다운 프리뷰 (스크린샷 톤 — 요약 띠 + 본문) |
| **퀴즈 결과** | 오늘의 퀴즈 점수·정답률·오답 수 + 본인이 틀린 문항 요약 |
| **오답노트** | **전체 누적 오답** (특정 날짜 제한 없음) — 빠른 복습용 |

### 5.1 에디터 톤 (스크린샷 매칭)

- 좌측: 제목 input (큰 폰트) + 마크다운 툴바(굵게·기울임·취소선·헤딩·인용·목록·번호·링크·이미지·표·코드) + 본문 textarea
- 우측: 흰 카드 + 3탭 + 패널

### 5.2 게시 후 액션 (v1.4 변경 — 외부 복사 제거)

- 게시된 TIL 상세 액션 = **`마크다운 복사`** + **`PDF 다운로드`** + `수정` (학생 본인)
- **외부 공유(공개 URL) 기능 제거** — TIL은 학습 기록이므로 외부 공개 다이얼로그·SNS를 두지 않음(v1.1의 외부 복사 폐지)

### 5.6 작성 진입 — 히트맵 날짜 선택 (v1.4)

- 작성하기 진입 시 **본인 활동 히트맵**으로 날짜 선택(작성·임시·미작성 색 구분). **오늘은 진한 테두리**, 선택 칸은 오렌지 링
- 선택 날짜 상태에 따라 `새 글 작성`/`수정하기`로 분기 (드롭다운 셀렉트 대체)
- 활동 히트맵(학생)·학생×주차 히트맵(매니저) 모두 **오늘 표시**(매니저는 세로 밴드)
- 작성 우측 **퀴즈 결과** 패널은 **전체 문항**(정답/오답 표시) 노출, **문항 클릭 시 상세 모달**(보기·정답·내 선택·해설)

### 5.3 활동 히트맵 — 주 7일 + 주말 (v1.1 신규)

- 활동 기록 히트맵을 **평일 5일 → 주 7일(월~일)** 로 확장
- 주말은 별도 패턴(**점선 보더·옅은 회색**)으로 "비학습일" 시각화
- 학생이 자율적으로 주말에 작성한 TIL도 표시

### 5.4 작성 진입 — 날짜 셀렉트 (작성/수정 통합, v1.1 신규)

- 작성하기 진입 시 **날짜 셀렉트** 우선 노출 (멋사 `lk-select`)
- 해당 날짜에 TIL 없음 → **새 글 작성** / 있음 → **수정** 모드로 분기
- 셀렉트 옵션에 날짜 + 작성 상태(`작성됨`/`임시`/`미작성`) + 우수 TIL `🏆` 표시

### 5.5 우수 TIL (매니저, v1.1 신규)

- 매니저가 학생 TIL에 **우수 TIL** 마크 가능
- 학생 히트맵에서 우수 셀은 차별화 — **오렌지 풀 + 별(★) 오버레이 + 진한 보더**
- **색약 대응** — 색 + 아이콘 동시 사용

## 6. 프로젝트 — 학생뷰 3탭(+제출 버튼) / 매니저뷰 2탭

### 6.0 태그 체계 (v1.3 — 단계 정의) ⭐

> 프로젝트는 **두 개의 독립 축**으로 표현한다: ① *프로젝트 자체*의 생명주기(**전체 단계**), ② *학생 본인 기준*의 진행(**내 진행 상태**). 여기에 **종류(회차)** 분류와 제출본 단위 **비공개·우수** 배지가 직교한다. 뷰에 따라 주(主) 배지가 다르다.

**① 종류(회차) 태그** — 분류용, 4종: `기초` / `심화` / `파이널` / `기타` (색상 구분). 학생·매니저 공통, 카드·상세 상단.

**② 전체 단계 (시스템, 날짜로 자동 전환)** — 제출 기간 `[제출시작, 제출마감]` + 피드백 기간 `[, 피드백마감]` 기준:

| key | 라벨 | 전환 조건 | 의미 |
|---|---|---|---|
| `scheduled` | 예정 | now < 제출시작 | 카드 생성됨, 제출 오픈 전 |
| `submitting` | 제출 진행 | 제출시작 ≤ now ≤ 제출마감 | 학생 제출·수정 가능 |
| `feedback` | 피드백 진행 | 제출마감 < now ≤ 피드백마감 | 제출 잠금, 매니저 피드백 작성 |
| `closed` | 종료 | now > 피드백마감 | 활동 종료, 열람만 |

> 제출마감~피드백시작 공백은 `피드백 진행`에 흡수(매니저 채점 준비 포함).

**③ 내 진행 상태 (학생 본인, 제출축+피드백축 결합)** — *학생뷰 주 배지*:

| key | 라벨 | 조건 | 다음 행동 |
|---|---|---|---|
| `not_submitted` | 미제출 | 제출 진행 중 · 본인 제출 없음 | 제출하기 |
| `draft` | 임시저장 | 임시저장만 함 | 이어서 작성 |
| `submitted` | 제출 완료 | 제출함 · 피드백 전 | 게시판 열람 |
| `feedback_ready` | 피드백 도착 | 본인 제출에 피드백 등록됨 | 피드백 확인 |
| `missed` | 미제출 마감 | 종료까지 미제출 | 열람만 |
| `not_open` | 오픈 예정 | 예정 단계 · 미제출 | 대기 |

**④ 제출본 단위 배지 (단계와 직교)** — `우수`(매니저 마크), `비공개`(매니저 모더레이션), `외부 발행`(학생 공유). 제출본 카드에만 노출.

**표시 위치 — 뷰별 표현 분리**

| 요소 | 학생뷰 | 매니저뷰 |
|---|---|---|
| 종류(회차) | 카드·상세 상단 | 카드·상세 상단 |
| 전체 단계(②) | **보조**(작게, 예: `제출 진행 D-3`) | **주 배지** + 제출률·피드백 필요 건수 |
| 내 진행 상태(③) | **주 배지**(카드 우측·상세 상단) | — |
| 제출본 배지(④) | 본인 제출본 안내(`비공개 처리됨` 등) | 제출현황·피드백 보드 카드 |

### 6.1 학생뷰 카드 표시 (정보 간소화)

| 항목 | 내용 |
|---|---|
| **종류 태그** | `기초` / `심화` / `파이널` / `기타` (좌측) |
| **전체 단계(보조)** | 예정/제출진행/피드백진행/종료 — 작게, D-day 부가 |
| **내 진행 상태(주)** | 미제출/임시저장/제출완료/피드백 도착/미제출 마감 — 카드 우측에 강조 |
| **표시 정보** | 제목 + 제출 기간 + 피드백 기간 (나머지 상세는 회차 내부) |

### 6.2 학생뷰 상세 — 3탭 + 제출 버튼 (v1.3 변경)

> **`제출하기`는 탭이 아니라 버튼**이다. **문제 설명 좌측**에 눈에 띄게 배치하고, 상태에 따라 라벨·활성이 바뀌어 단계를 한눈에 보여준다.

탭(3): **문제** / **제출 프로젝트 리스트** / **받은 피드백**

**제출 버튼 (문제 탭 좌측 CTA)**

| 전체 단계 | 본인 제출 | 버튼 | 활성 |
|---|---|---|---|
| 제출 진행 | 없음 | **`제출하기`** | 활성 |
| 제출 진행 | 있음 | **`수정하기`** | 활성 |
| 예정 | — | `제출 오픈 예정` | 비활성 |
| 피드백 진행/종료 | 있음 | `제출 완료 (수정 마감)` | 비활성 |
| 피드백 진행/종료 | 없음 | `제출 기간 종료` | 비활성 |

- 버튼 옆/아래에 **내 진행 상태 + 마감 D-day** 보조 노출 → 기간이 지나면 버튼이 **자동 비활성**되어 단계를 즉시 인지.
- 버튼 클릭(활성 시) → 제출/수정 폼(fullpage) 진입.
- 탭별: **문제**(설명 + 좌측 제출 CTA) / **제출 프로젝트 리스트**(본인 맨 앞·미제출 시 잠금) / **받은 피드백**(본인만).

### 6.3 외부 공유 다이얼로그 (v1.1 변경 — 제출 폼 토글 제거)

- **제출 폼의 `외부 발행` 토글 제거** — 워크플로 분기 단순화
- 외부 공유는 제출 후 **`제출 프로젝트 리스트` → 본인 제출본 → `외부 공유하기`** 다이얼로그에서만 처리
- 다이얼로그(v1.3): **외부 공유 토글(ON/OFF)** + **링크 복사**만. 토글 ON = 공개 링크 생성·열람 가능, OFF = 링크 비활성화(비공개). **SNS 연동 버튼 없음**
- 기본 비공개. 학생이 토글을 켜야 외부 공개되고, 언제든 끌 수 있음

### 6.4 매니저뷰 카드 (정보 풀세트)

제목 + 제출 기간 + 피드백 기간 + 제출 훈련생(N명/전체 N명) + 제출 비율(%) + **전체 단계(주 배지)** + 종류 태그. (내 진행 상태는 매니저뷰 비노출)

### 6.5 매니저뷰 상세 — 2탭 (v1.3 변경 — 피드백 탭 폐지, 제출현황으로 통합)

- 상단 액션 **`프로젝트 정보 수정`** (구 `회차 수정`) — 클릭 시 **모달**로 등록 시 입력 항목 전체(회차 종류·회차명·한 줄 소개·문제 설명·제출/피드백 기간) 수정
- 상세 헤더는 리스트와 동일 우선순위: **제목 + 회차** → **전체 단계** → 제출/피드백 기간 + 제출률

탭(3, v1.4): **문제** / **제출현황** / **미제출명단**

**제출현황 탭 (피드백 통합)**
- **필터**: `전체` / `피드백 전` / `피드백 완료`
- 제출본 카드 **썸네일 위 태그**로 `피드백 완료`/`피드백 전` 표시 + **우수 ★ 썸네일 오버레이** + `공개 중` 배지
- 카드 클릭 → 제출본 상세(내용) + **하단에서 피드백 등록·수정**, `우수 마크` / **`공개 설정`**(공개 상태·링크 보기/수정 다이얼로그 — v1.4에서 `비공개 전환` 대체)
- 피드백 작성은 제출현황 안에서 진행. 피드백 기간과 무관하게 작성 가능(기간 태그 제거)

**미제출명단 탭 (v1.4 신규)**
- 제출하지 않은 학생 리스트만 표시(번호·이름·`미제출` 태그). 탭 라벨에 미제출 인원 수. 전원 제출 시 빈 상태 안내
