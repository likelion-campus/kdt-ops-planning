# 클래스룸 Figma 풀페이지 v2.4 — 블루프린트

## 0. 목적 · 방향 전환

**왜 다시 만드는가.** 기존 Figma(`figma-frames/`, 파일 `8pi9c1Q2cmf47GPnjbdi9B`)는 **신규 스펙 중심 어노테이션 보드**라 화면 일부·컴포넌트 단위로 흩어져 있었다. 디자이너가 "이게 한 화면에서 어떻게 보이나"를 조립해야 했다.

**이번 방향(v2.4).** 프로토타입의 **완성된 한 화면(GNB+LNB+본문 포함, 1280px)** 을 그대로 **풀페이지 프레임**으로, **상태별(기본·빈상태·에러)** 로 펼쳐 놓는다. → 디자이너는 조립이 아니라 **다듬기**만 하면 된다.

> 한 줄 원칙: **"화면 = 프레임", 상태 = 프레임 변형."** 컴포넌트 추출·variant 정의는 디자이너 몫으로 남긴다(우리가 미리 쪼개지 않는다).

## 2. 산출물 정의 (1 프레임 = 1 풀페이지)

- 각 프레임은 **셸 포함 완성 화면**: 상단 GNB(로고·내비·뷰토글) + 좌측 LNB + 본문.
- 폭 **1280** 고정, 높이는 콘텐츠 hug(세로 오토레이아웃).
- 폰트 **Noto Sans KR**(Figma 조직에 Pretendard 미존재), 색은 `tokens.css` hex 직접 적용(브랜드 primary `#FF6000`).
- 로고는 프로토타입 최신 자산(`assets/logo-mussa-bootcamp.png`) 반영.
- 프레임 상단에 얇은 **상태 라벨 칩**(기본/빈상태/에러)만 주석으로. 그 외 어노테이션 최소화(디자이너 작업 방해 X).

## 3. Figma 파일 구조 (페이지 = LNB 영역)

```
[파일] 클래스룸 풀페이지 v2.4
├─ 00 · 표지 + 인덱스           (변경 요약, 프레임 맵, 토큰 레퍼런스)
├─ 01 · 셸/공통                 (학생·매니저 셸 가이드, 빈상태·에러 패턴, 공용 다이얼로그)
├─ 02 · AI 노트                 (학생/매니저)
├─ 03 · AI 퀴즈                 (학생/매니저)   ← 이번 라운드 핵심
├─ 04 · TIL                     (학생/매니저)
└─ 05 · 프로젝트                (학생/매니저)
```

각 페이지 안에서 **행=뷰(학생/매니저)**, **열=상태(기본/빈/에러)** 그리드로 배치(좌→우 상태, 위→아래 화면 흐름).

## 5. 실행 계획 (단계별 — figma-use 증분 워크플로)

> `figma-use` 스킬 필수 선로딩 → `create_new_file` → 페이지/프레임 증분 생성, 단계마다 스크린샷 검증.

| 단계 | 내용 | 검증 |
|---|---|---|
| **P0. 기준 세팅** | 새 파일 생성 + 00/01 페이지 + **AI 퀴즈 Q9(퀴즈 발행하기) "기본" 1프레임**을 레퍼런스 퀄리티로 완성 | 스크린샷으로 톤·간격·로고·토큰 컨펌 **(여기서 사용자 승인 게이트)** |
| **P1. AI 퀴즈** | 03 페이지 Q1~Q16 전 상태 생성 | 페이지 스크린샷 |
| **P2. TIL** | 04 페이지 T1~T7 | 스크린샷(가로 스크롤 표현 확인) |
| **P3. 프로젝트** | 05 페이지 P1~P9 | 스크린샷 |
| **P4. AI 노트** | 02 페이지 N1~N5 | 스크린샷 |
| **P5. 마감** | 00 표지·인덱스·토큰 레퍼런스 채우고 `README.md`(프레임↔node-id 맵) 작성 | 전체 점검 |

- **헬퍼 재사용**: 이전 작업의 `screen()` 헬퍼(세로 오토레이아웃 hug, `resize` 후 `primaryAxisSizingMode='AUTO'` 리셋) 패턴 그대로.
- **배치 규칙**: 1 use_figma 호출 ≤ 10 논리 작업. 프레임은 상태별 가로, 화면별 세로 그리드.

## 7. 비고 · 한계

- 인터랙션(클릭→전환)은 정적 프레임으로만. 동작은 HTML 프로토타입(`../prototype/`)이 SSOT.
- 토큰은 hex 직접 적용 → 디자이너가 Figma 변수 컬렉션으로 승격 시 일괄 관리.
- 구 `figma-frames/`(컴포넌트/어노테이션 보드)는 **참고용 보존**, 본 v2.4가 디자이너 인계 기준.
- 프레임 수가 많아 **P0 승인 후** 일괄 생성 권장(레퍼런스 1장으로 방향 먼저 합의).
