## 1. 권한 정의

> **클래스룸 내 권한은 2종(학생/매니저)**로만 운영한다. 매니저 권한 하나로 강사·퍼실·운영담당자가 동일하게 사용한다. 분반·강의 필터링은 사용자별 자체 적용.
> **단, 캠프파이어·Admin 도메인 권한은 4종(학생/강사/퍼실/매니저)**으로 별도 운영한다 — 채널·운영 정책이 다르기 때문. 클래스룸 매니저는 캠프파이어·Admin 상에서는 본인의 직책 권한(강사·퍼실·매니저)으로 분리되어 동작한다.

### 1.1 클래스룸 내 권한 (2종)

| 권한 | 한 줄 정의 | 사용자 |
|---|---|---|
| **학생** | 매일 학습·산출 주체 | 훈련생 본인 |
| **매니저** | 해당 수업 운영·콘텐츠 책임 | 강사 · 퍼실 · 운영담당자 (동일 권한 공유) |

### 1.2 캠프파이어 · Admin 권한 (4종, 참고)

| 권한 | 한 줄 정의 |
|---|---|
| **학생** | 본인 학습·소통 |
| **강사** | 수업 진행·콘텐츠 책임 |
| **퍼실** | 학습 보조·소그룹 운영 |
| **매니저** | cohort 운영·일정·관리 |

### 1.3 권한과 시나리오는 분리

- **권한** = 어떤 데이터에 접근 가능한지 (§6 권한 매트릭스에서 메뉴별 정의)
- **시나리오** = 사용자가 해당 메뉴에서 실제로 어떤 일을 하는지 (§4 메뉴별 사용자 시나리오에서 정의)

## 4. 메뉴별 사용자 시나리오 · 페이지 구성 · 기능 명세

> 각 메뉴는 **(A) 페이지 구성 — (B) 학생 시나리오 — (C) 매니저 시나리오 — (D) 액션·반응·상태 — (E) 빈상태·에러** 순서로 정리.

---

### 4.1 AI 노트 — 스코프 외 (현행 유지)

카드 리스트 + 인라인 본문 펼침 + 검색 UX 현재 그대로 유지.
**단, TIL 작성 폼(4.4) 우측에 컨텍스트로 함께 노출되는 연동만 신규.**

> **매니저 수정 표시 · 원본 복구 (v1.4 신규, POL-CR-03 §4)**: 매니저가 AI 노트 본문을 수정·발행하면 상세에 **`수정됨 · 시각` 배지**가 노출되고(학생·매니저 공통), 최초 수정 시 **원본(제목·요약·본문)을 백업**한다. 잘못 수정한 경우 매니저 상세의 **`원본 복구`** 버튼(확인 모달)으로 수정 전 상태로 되돌리고 배지를 제거할 수 있다(백업 정책).

---

### 4.2 학습퀴즈 (구 AI 퀴즈 · 오답노트·보충 퀴즈 흡수)

> **메뉴명 (PRD v1.4)**: `AI 퀴즈` → **`학습퀴즈`**, 일일 `오늘의 퀴즈` → **`학습퀴즈`** 로 통일. (AI 문항 생성 액션 `AI 퀴즈 생성`·`AI 문항 생성` 라벨은 유지)
> 페이지명: **"학습퀴즈"** · 부제 "학습한 내용을 퀴즈로 점검해보세요."
> **v1.4 UX 반영(POL-CR-03 v1.4)**: 출제 후 제목 `오늘의 퀴즈 ｜ 제목 ｜ 객관식 10문제` / 결과 하단 `ALEX 복습하기`·`보충 퀴즈 풀기` / 오답노트 **검색+페이지(20/50/100)** / 보충 **한도 학생 비표시**·대상 날짜 **카드 선택(퀴즈 제목·최대5·최근5 기본)** / 매니저 발행본 `퀴즈 수정`+`추가 퀴즈 생성`·보충현황 **월별 페이지네이션**
> **확정**: 객관식 10문제

#### (A) 페이지 구성

**학생뷰 탭 3종** (왼쪽 정렬 버블/pill — v1.8)

| 탭 | 학생 동작 |
|---|---|
| **강의퀴즈** | 오늘 응시 가능한 블럭(날짜·제목·문항수 / 우측 응시 가능·`퀴즈 풀기`) + 과거 응시 결과 리스트. **학생뷰는 소요시간을 일절 표시하지 않음 — 응시 중·결과 화면·과거 리스트 모두 비표시**(v1.9 — v1.8 "결과 화면 표시" 번복). 미응시 날 클릭 시 풀기 진입 |
| **오답노트** | **리스트+드롭다운 펼침** — 행(출처태그·날짜·제목·책갈피·메모) 클릭 시 보기+정답+해설+인라인 메모. 필터 `전체/강의퀴즈/보충퀴즈/책갈피/메모`. **강의퀴즈+보충퀴즈 오답 통합(D1)**. 액션은 `메모`·`책갈피`, 다시 풀기 없음(정답 전환 X) |
| **보충퀴즈** | 학생이 직접 **출제**(대상 날짜 **리스트+페이지네이션**·오답중심·문항수). 생성 시점 기준 리스트 누적. 풀이 후 **전용 결과 뷰**(**소요시간 미표기**(v1.9)·ALEX/보충풀기 CTA 없음). **내부 하루 10회 제한(학생 비표시, 초과 시 "오늘은 쉬어가요")** |

**매니저뷰 탭 3종** (학생뷰와 메뉴 다름 — 오답노트는 매니저에 노출 X, 학생 자기학습 영역 보호)

| 탭 | 매니저 동작 |
|---|---|
| **퀴즈 발행하기** (v1.7 서브탭, 구 `오늘의 Draft`) | **`발행 예정`/`임시 저장` 2서브탭** → 슬롯 클릭 시 편집/발행 폼. 상단 고정 액션 **`AI 퀴즈 생성`·`임시저장`·`예약발행`·`즉시발행`**. 상태 = 임시저장/예약발행/발행됨. (default 08:30) |
| **발행된 퀴즈** | 발행본 리스트 + 문항별 오답률·보기 선택 분포(09:30 리뷰). 발행본 `퀴즈 수정·재발행` 진입 |
| **보충 퀴즈** | 학생별·날짜별 보충 퀴즈 사용수 히트맵 — 집계 기준 **푼 날짜** · 하루 **10회(세트)** = 가장 붉은 색 |

> **보충 퀴즈** = 학생의 누적 오답을 기반으로 학생이 직접 생성하는 추가 문제. **내부적으로 하루 10회(세트) 제한** — 학생에게는 횟수·한도를 표시하지 않고, 한도 초과 시에만 "오늘은 쉬어가요" 안내(POL §2). 매니저는 사용수 통계만 확인.
> **오답노트는 강의퀴즈+보충퀴즈 오답을 통합한다 (v1.8 변경, D1)** — 오답노트에 **강의퀴즈·보충퀴즈 양쪽 오답**이 누적되고, 출처 필터(`전체/강의퀴즈/보충퀴즈/책갈피/메모`)로 구분해 본다. 단 **오답노트에서 다시 풀기 액션은 없고**(다시 풀어도 정답으로 전환되지 않음), 보충퀴즈 응시 자체는 보충 탭에서 별도로 한다. *(직전 v1.x의 "오답노트와 보충은 분리" 조항을 통합으로 개정)*

#### (B) 학생 시나리오

**학습퀴즈 탭**
1. D 08:30 발행 안내(매니저 현장 안내) → 메뉴 진입
2. 오늘 카드 `학습퀴즈 풀기` 버튼 클릭 → 진행률 바 + 본문 한 화면씩 진행
3. 문항당 보기 선택 → 하단 `제출하기` 활성 → 클릭 시 다음 문항
4. 10번째 제출 직후 즉시 채점 결과 + 해설 페이지 노출 → 오답은 자동으로 `오답노트` 탭에 누적
5. 재진입 시 결과 페이지 강제 (재응시 차단) — 오늘 날짜의 결과 보기
6. 과거 결과: 날짜별 리스트에서 카드 클릭 → 그날 결과 세부 (미응시한 날로 진입하면 그날 문제 풀기 가능, 한번 푼 다음은 결과보기로 전환)

**오답노트 탭**
1. **날짜별 문제 리스트**로 진입 (필터: 날짜 · 책갈피)
2. 카드 클릭 → 그날 틀린 문제 세부 — **객관식 전체 문제 + 본인이 선택한 보기 표시 + 정답 + 해설**을 한 화면에 노출
3. 문제별 액션은 **`메모 추가` · `책갈피`** 두 가지뿐
4. **다시 풀기 액션 없음** — 오답을 다시 푼다고 정답으로 전환되지 않는다 (복습 기록 보호)
5. `책갈피` 필터 — 책갈피한 문제만 표시

> **UX 개선 과제 (오픈)**: 과거 오답 리스트 표현 방식은 추가 개선 검토 필요 (현재 프로토타입 기준으로 아쉬움 있음).

**보충 퀴즈 탭** (오답노트와 분리)
1. `보충 퀴즈 생성` (날짜별 선택, 오답중심 선택, 문제 수 선택) 옵션 기반으로 문제 생성 후 바로 풀기
2. 생성 시점 기준 리스트에 1개씩 추가 — **결과는 보충 퀴즈 탭 내부에만 누적**되며 오답노트 상태에 영향 X
3. 하루 10회(세트) 한도 초과 시 — 학생에겐 횟수를 표시하지 않고 "오늘은 쉬어가요" 안내(생성 버튼 비활성)

#### (C) 매니저 시나리오

**퀴즈 발행하기 탭** (v1.7 서브탭 — POL-CR-03 v1.7 §1.4)
1. 발행 대기 **슬롯 리스트**(상태·예약 일시·이름·문항수)에서 슬롯 클릭 → 편집/발행 폼. `새 퀴즈 추가`(primary solid) 시 빈 슬롯 생성 후 곧바로 제작. 정책 안내는 **📌 제목 + 3 bullet 박스**로 상단 고정.
2. 편집 폼 상단 고정 액션: **`AI 퀴즈 생성` · `임시저장` · `예약발행` · `즉시발행`**. *(단위: 퀴즈 > 문항 > 문제·객관식·답·해설)* **세 액션(`임시저장`·`예약발행`·`즉시발행`) 모두 빈 칸 검증을 거친다 — 빈 필드가 있으면 실행 차단 + 인라인 에러**(v1.9, §4.2 E).
3. **AI 퀴즈 생성**(퀴즈 전체·overwrite): **(a) AI 노트 기반**(노트 복수 선택) / **(b) 입력 기반**(개념 텍스트) + **생성 문항 수**(5/10/15). 기존 문항 있으면 덮어쓰기 경고.
4. 문항 인라인 편집(문제·보기 1·2·3·4·정답·해설). **문항별 `AI 문항 생성`** = 입력 개념 기반 객관식 1문항 자동 생성 후 해당 문항 덮어쓰기.
5. **상태 모델**: 예약·발행 전엔 **임시저장**. **예약발행**(일시 지정·이 경우에만 예약 일시 노출) / **즉시발행** 시 `발행된 퀴즈` 탭으로 이동.
6. **발행 이후 수정 제한**: 정답·보기 번호 잠금, **텍스트(문항·해설)만 수정**. 발행본 텍스트 수정·AI 재발행 시 응시 결과 재집계 + 학생뷰 **수정됨 · 시각** 배지.
7. **생성 실패 시 (v1.5)**: **학생뷰에는 노출하지 않고**(그날 퀴즈 미발행과 동일) **매니저뷰에서만** 표시 + **즉시 재생성**(재생성 → 검토 → 발행) 제공. default 08:30(휴일 제외, 다음 수업일 진행).
8. **다중 발행 + 발행 서브탭 (v1.7)**: 추가 발행은 **생성일 기준 하루 최대 20개**. `퀴즈 발행하기` 탭은 v1.5의 날짜 기준 2구획을 **상태 기준 2서브탭**으로 재편한다 — **`발행 예정`**(예약발행 슬롯 전체를 **발행일시 오름차순**으로, 목록 우측에 `오늘 생성 퀴즈 수 · N/20` 카운터, 다건 시 **페이지네이션** 10개/페이지) / **`임시 저장`**(임시저장·생성실패 슬롯). 입력 기반 생성에는 **예시 프롬프트 안내** 제공. *(디자이너 시안 Figma 11665:39011 반영. 시안 "출제 예정"은 보충 퀴즈 전용어 `출제`와 충돌하여 `발행 예정`으로 표기. 리스트는 테이블화하지 않고 슬롯 행 유지.)*

**발행된 퀴즈 — 발행본 상세 (v1.5 3탭, v1.4 응시시간 추가)**

> **상단 액션 (v1.10)**: 발행본 상세 상단 고정 액션은 **`퀴즈 수정` · `퀴즈 풀이` · `추가 퀴즈 생성`** 3종이다. `퀴즈 풀이`는 `퀴즈 수정` 바로 옆에 배치한다(스크린샷 시안 기준).

**`퀴즈 풀이` (수업용 — v1.10 신규)**
- 강사가 **수업 중 학생들과 함께** 발행본 퀴즈를 한 문제씩 풀어보는 진행 도구다. 학생 응시(§4.2 B)와 **UI 흐름은 같지만**(한 화면 한 문항·보기 선택), 차이는 아래와 같다.
- **한 문제씩 진행 + 즉시 정답·해설 공개**: 보기를 고르고 `정답 확인`을 누르면 그 문항의 **정답·해설을 바로 노출**한다(선택 보기 정답/오답 하이라이트). 이어서 `다음 문항`으로 넘어가고, 마지막 문항에서 `퀴즈 풀이 마치기`로 종료. *(학생 응시는 10문항을 모두 풀고 마지막에 일괄 채점하지만, 퀴즈 풀이는 매 문항마다 즉시 정답을 공개하는 점이 다르다.)*
- **채점·집계·오답 누적 없음**: 강의 진행용이므로 학생 응시 결과(점수·소요시간·오답노트)에 **전혀 반영하지 않는다**. 발행본 KPI/통계에도 영향 없음.
- 진입: 발행된 퀴즈 → 발행본 상세 상단 `퀴즈 풀이`. **매니저뷰 전용**(학생뷰에는 없음).

각 발행본 클릭 시 3탭:
- **퀴즈 결과 요약 (v1.8)**: KPI **4종(응시율·평균 점수·하위권 비율·평균 소요시간)** — `정답률`→**`하위권 비율`(60점 미만=점수<6 학생 비율)**로 교체, **`목표 15분` 표기 제거**. 미응시는 KPI에서 제외하고 `미응시 명단` 탭에서 확인 + 문항별 **오답률 · 평균 소요시간(난이도 `쉬움/보통/어려움`) ·** 보기 선택 분포
- **학생별 점수**: 점수순 리스트(정답률·점수·**소요시간 ⏱ = 본인 실제 총 시간**) + **학생 클릭 시 개별 결과·오답 드릴다운**(본인 총 소요시간 + **문항별 본인 실제 소요시간**(평균 아님) — 매니저뷰 전용, 학생 결과 화면에는 미표시(v1.9))
- **미응시 명단**: 미응시 학생 리스트만 표시 (**`알림 보내기`/DM 자동 전송 기능 제거** — 명단만)

> **소요시간 = 매니저뷰 진단 전용 (v1.9)**: 소요시간 데이터(KPI 평균·문항별 평균/난이도·학생별·개별 드릴다운)는 **매니저뷰에서만** 표시한다. **학생뷰에는 응시 중·결과 화면·과거 리스트·보충퀴즈 결과 어디에도 소요시간을 표시하지 않는다** (v1.8 "결과 화면 종합+문항별 표시" 번복).

> **중도포기자 집계 = `퀴즈 생성 시점` 기준 (v1.12, POL-CR-03 §1.2.3)**: 발행본 상세 3탭(결과 요약 KPI·학생별 점수·미응시 명단)과 `발행된 퀴즈` 리스트 행의 **응시율·평균·미응시 수는 그 퀴즈 생성일 기준 재적생**(중도포기자 제외)만 집계한다. **생성 이후 중도포기자는 응시 점수를 보존**해 학생별 점수에 그대로 노출하고(`중도포기` 배지로만 식별, 흐림·잠금 없음), **생성 시점에 이미 중도포기한 학생은 발행본 상세·리스트 집계에서 제외**한다. 발행본 상세 상단에 **`퀴즈 생성 시점(YY.MM.DD) 기준 재적생`** 안내를 노출하고, **중도포기자 현황은 출결현황에서 확인**하도록 가이드한다. *(보충 퀴즈 사용현황 히트맵은 특정 퀴즈 시점이 없는 누적 뷰이므로 본 규칙에서 제외 — 기존 표시 유지.)* 데이터 `droppedAt` + 헬퍼 `isDroppedAsOf` (프로토타입 `ai-quiz.html`·`mock-data.js`·`components.js`).

> **ALEX 복습 품질 (v1.4)**: 학생 결과 화면의 `ALEX 복습하기`는 캠프파이어 ALEX로 오답 컨텍스트를 전달한다. **첫 답변부터 고품질**, **틀린 문제 중심 개념 설명·점검 → 미니 퀴즈 → 문답**이 이어지도록 하며, 출시 전 **실제 테스트로 품질을 검증**한다(대화 UI·프롬프트는 ALEX 측, 클래스룸은 오답 컨텍스트 전달+진입점) — POL-CR-03 §1.6.

> **보충 히트맵 = 풀이 완료 세트만 집계 (v1.13, POL-CR-03 §2.1)**: 매니저 보충 퀴즈 사용현황 히트맵의 셀 강도(일별 풀이 횟수)와 **셀 클릭 상세 리스트**는 **`풀이가 완료된(제출된)` 보충 세트만** 집계한다. 학생이 **출제(생성)만 하고 풀지 않은 세트는 히트맵·셀 클릭 어디에도 포함하지 않으며**, 집계 기준일 = **학생이 그 세트를 푼 날짜**다(미완료 세트는 푼 날짜가 없어 어느 날짜 셀에도 잡히지 않음). 프로토타입은 `SUPP_SOLVED_DAILY`(`set.solved && solvedAt`) + `openMgrSuppDetail`의 solved 필터로 이미 반영.

**보충 퀴즈 탭**
- 학생별·날짜별 보충 퀴즈 사용수 히트맵 — **풀이 완료(제출)한 세트만**, **푼 날짜 기준** 집계 · 하루 10건이 가장 붉은 색(v1.13)
- 셀 클릭 시 그날 **풀이 완료한** 보충 세트 리스트 + 정답률 확인
- 매니저는 발행·생성 트리거 없음. 학생이 직접 만든 통계만 확인

### 4.3 실습

> 메뉴명 UI 표기: **실습**. AI 표기 제거. 강사가 직접 등록한 실습 문제만 노출.

#### (A) 페이지 구성

- **날짜별 리스트** — 하루에 여러 실습 문제 발행 가능
- 각 날짜 세부 페이지에 그날 발행된 문제들이 리스트로 표시
- 학생은 본인의 제출 유무를 한눈에 확인
- 매니저는 발행 + 채점 화면 별도

#### (B) 학생 시나리오

1. 날짜별 리스트 → 그날 카드 클릭 → 그날 발행된 문제 리스트
2. 문제 진입 → 평가기준 확인 → 제출
3. 제출 항목 — **텍스트 (필수)** + 파일 + 이미지 + URL (모두 선택)
4. 본인 제출 유무 카드에 표시 (`제출 완료` / `미제출`)
5. 채점되면 점수 + 코멘트 노출 (둘 다 옵션 — 채점 안 될 수도 있음)

#### (C) 매니저 시나리오

**발행**
1. 매니저뷰 → `문제 작성` → 제목·설명·평가기준 작성
2. **발행 시간 설정** — 날짜·시간 예약 발행 또는 즉시 발행
3. **캠프파이어 공지 옵션** — 발행 시 알림 채널·메시지 함께 등록 가능 (§8 알림 참고)
4. 발행 후 학생 리스트에 카드 푸시

**채점**
1. 채점 뷰 → 날짜 선택 → 학생별·문제별 제출 유무를 **표 형태**로 표시 (제출자 = 색상 / 미제출 = 회색)
2. 셀 클릭 시 제출 상세 확인 가능
3. 점수 (옵션) + 코멘트 (옵션) — 둘 다 자유 운영. 점수·코멘트 입력 필드 제공

#### (D) 액션·반응·상태

| 액션 | 시스템 반응 | 다음 상태 |
|---|---|---|

### 4.4 TIL

> 페이지명 "나의 TIL", 부제 "매일 배운점을 정리해보세요"
> **v1.4 UX 반영(POL-CR-03 §5.2·§5.6)**: 게시 후 액션 = **마크다운 복사 + PDF**(외부 공유 제거) / 작성 진입 시 **활동 히트맵으로 날짜 선택** / 활동·매니저 히트맵 **오늘 표시** / 작성 우측 퀴즈결과 **전체 문항 + 문항 상세 모달**
> **PRD v1.4 (6/5, POL-CR-03 §5.7)**: 작성 폼 우측 `퀴즈 결과` 패널에서 문항을 **TIL 본문에 한 블록으로 붙여넣기**(문항별 `붙여넣기` + 상단 `전체 붙여넣기`, 마크다운 블록 삽입). 매니저 `해당 수업 TIL` 학생×날짜 히트맵은 **월별 페이지네이션**으로 분할해 스크롤 부담을 줄인다(이전/다음 달).

#### (A) 페이지 구성

- 상단: **활동 기록 히트맵** (3색 — 미작성 · 임시 · 작성)
- 하단: 본인 작성 카드 리스트 (탭: 리스트 / 카드)
- 우상단: `작성하기` 진입 버튼

**작성 폼 — 좌·우 분할**
- 좌측 패널: 제목 + 마크다운 본문 에디터 1개 (단일 폼)
  - 빈 본문에 템플릿 placeholder 자동 삽입 — `# 오늘 배운것` · `# 막힌것` · `# 내일 할 것` (마크다운 헤더 형식)
- 우측 패널: **오늘의 컨텍스트 3종 자동 표시 (참조용, 읽기 전용)**
  - 오늘의 AI 노트
  - 오늘의 오답노트
  - 오늘의 실습 (문제 + 본인 제출 결과 — 미제출 시 안내 메시지)

#### (B) 학생 시나리오

1. LNB → "TIL" → 활동 기록 히트맵 + 본인 작성 카드 리스트
2. `작성하기` → 작성 폼 진입 (좌 폼 + 우 컨텍스트 3종)
3. 작성 중 자동 저장 (`임시` 상태). `게시하기` 클릭 시 `작성` 상태로 전환 → 히트맵 색 즉시 갱신
4. **게시 이후에도 자유 수정 가능** — 게시일 잠금 없음, 언제든 수정 가능. 수정 시 본인·매니저 화면 모두에 **최근 수정 시간 + `수정됨` 표시**가 노출됨
5. 카드 리스트에서 과거 TIL 클릭 → 본문 열람·수정

#### (C) 매니저 시나리오

1. 매니저뷰 → TIL → **행 = 학생 이름**, **열 = 날짜**로 히트맵 표시 (3색 — 미작성 · 임시 · 작성, 범례 안내 문구 표시)
2. **히트맵 셀 클릭 시 세부 진입** — 해당 학생·날짜의 TIL 본문 슬라이드 패널
3. 작성률 낮은 학생은 히트맵에서 자연스럽게 회색으로 식별됨

#### (D) 액션·반응·상태

| 액션 | 시스템 반응 | 다음 상태 |

### 4.5 프로젝트

> **운영 회차(종류)**: 기초 · 심화 · 파이널 (기본 3종) + `기타 프로젝트` (매니저 선택으로 추가)
> 각 회차에 **제출 기간** + **피드백 기간** 분리
> **태그 체계(v1.5, POL-CR-03 §6.0)**: ① **전체 단계**(예정·**제출 마감 D-N**·**피드백 진행중**·종료, 날짜 자동) ② **내 진행 상태**(미제출·임시저장·제출완료·미제출마감, 학생 본인 — **피드백 도착은 상태값에서 분리해 별도 메시지 아이콘**) ③ 제출본 단위 **외부 공개 제한·우수** 배지. **학생뷰=내 상태 주·전체 단계 보조 / 매니저뷰=전체 단계 주.**

#### (A) 페이지 구성

- 등록된 프로젝트들이 리스트로 보임
- 학생뷰 — 프로젝트 리스트 중 하나를 클릭하면 상세 페이지 진입. **`제출하기`는 탭이 아니라 문제 설명 좌측의 버튼**(제출 시 `수정하기`, 기간 외 자동 비활성)
- 매니저뷰 — `프로젝트 등록하기` 메뉴 (매니저에게만 표시). 클릭 시 프로젝트 생성 폼 (제목·설명·마감기한·피드백기한·프로젝트 URL·첨부파일·시연 영상 URL·발표자료) — **필수**: 제목·설명·프로젝트 URL·발표자료·시연 영상 URL

#### (B) 학생 시나리오 — `프로젝트 제출하기`

1. 프로젝트 메뉴 진입 → 프로젝트 리스트 → 카드 클릭 시 상세 진입
   - 카드 표면(학생): 회차명(기초/심화/파이널/기타) · **전체 단계 보조(D-day)** · **내 진행 상태 주 배지** · 제출 기간 · 피드백 기간
2. 상세 진입 → **문제 설명 좌측 `제출하기` 버튼**(본인 제출 있으면 `수정하기`) → 제출/수정 폼 진입. 제출 진행 기간이 아니면 버튼 비활성(예: `제출 기간 종료`)
3. **다른 학생들의 제출물은 제출 기간이 끝난 뒤(= 피드백 기간부터) 전체 공개** (v1.4 변경) — 제출 기간 중에는 `제출 프로젝트 리스트` 잠금(문제만 표시), **피드백 기간 진입 시 제출 여부와 무관하게** 게시판 형태로 모든 제출본 공개. 이때부터 제출물 **수정 불가**(§4.5 6 수정=제출 기간만 정책과 정합). 최초 진입 기본 탭은 `문제`. (구 정책 "본인 제출 후 열람"에서 변경 — 베끼기 방지 + 마감 후 일괄 공개)
   - **내 제출본 고정 + 페이지네이션 (v1.10)**: 제출 프로젝트 리스트는 **본인 제출본을 1페이지 맨 앞에 고정**(`내 제출본` 배지·아웃라인)해 항상 가장 먼저 보이게 한다. 본인 제출본은 페이지네이션 대상에서 **제외**하므로 **2페이지부터는 본인 제출본이 보이지 않는다**(다른 학생 제출본만 페이지당 N건). 다른 학생 제출본은 페이지로 나눠 `이전/다음`으로 탐색한다.
4. **피드백은 본인만 확인 가능** — 본인 제출물 아래 받은 피드백이 표시됨. 다른 학생에게 보이지 않음

**폼 구성**

기본 정보
- 프로젝트 제목 (필수)
- 프로젝트 한 줄 소개 (필수)
- 프로젝트 설명 (필수, 마크다운) — 빈 본문 시 가이드 placeholder 자동 삽입:
  ```
  # 문제 정의
  # 핵심 기능
  # Tech Stack
  # 주요 트러블슈팅
  # 팀 소개
  ```
- 메인 이미지 (필수)

제출 정보
- 프로젝트 URL (필수, 다중) — GitHub · Web · Figma 등
- 프로젝트 시연 영상 URL (필수) — YouTube / Vimeo
- 첨부파일 (선택)
- 발표자료 (선택)

5. `임시저장` 또는 `제출하기` — 제출 시 수업 클래스 내 게시판 공개. **임시저장만 한 상태에서도 메인 CTA는 `제출하기` 유지**(라벨을 바꾸지 않음), 클릭 시 **임시저장 내용을 불러와 이어 작성**(v1.5 결정 1)
6. **제출은 회차당 1건**. **수정 가능 여부는 제출 기간으로만 결정** — 제출 기간 중이면 **피드백 도착 여부와 무관하게 수정 가능**, 제출 마감 이후 수정 불가(버튼 비활성) (v1.5 결정 2)
7. 외부 공유는 **제출 폼 토글 없음** — 제출 후 `제출 프로젝트 리스트 → 내 제출본 → 외부 공유하기`에서만 공개 링크 생성. **매니저가 사유 입력으로 외부 공개를 제한**할 수 있고, 제한 사유는 학생 외부 공유 화면에 표시되며 **해제는 매니저만**(POL-CR-03 §6.3)

#### (C) 매니저 시나리오 — `프로젝트 등록하기`

1. `프로젝트 등록하기` 버튼으로 신규 회차 출제 / 등록 후 상세 상단 **`프로젝트 정보 수정`**(모달)로 전체 항목 수정. **전체 단계 `예정`(= 제출 시작 전, 발행 전)인 회차는 상세 상단 `프로젝트 삭제`(확인 모달)로 삭제 가능 — 제출 시작(발행) 이후에는 삭제 불가·버튼 미노출**(v1.9)
2. 회차 종류 선택 — 기초 / 심화 / 파이널 / 기타
3. 회차 메타 입력 — 제출 기간(시작·마감), 피드백 기간(시작·마감), 회차명, 한 줄 소개, 문제 설명
4. 상세는 **3탭(문제 / 제출현황 / 미제출명단)** (v1.4). 리스트는 **진행 중(제출>피드백) 우선 정렬**, 카드는 제목+종류 → 전체 단계 → 기간 + 우측 제출률 통계. **미제출명단** = 미제출 학생 리스트만(번호·이름)
   - **중도포기자 집계 규칙 (v1.11)**: 카드·상세의 **전체 학생수(분모)·제출률 분자는 중도포기자를 제외한 재적생** 기준이며, **전체 인원 옆에 `중도포기자 제외` 안내 텍스트**를 노출한다. **미제출명단·미제출 인원 수는 재적생 중 미제출자만**(중도포기자는 미제출로 세지 않음 — 기존 미제출+중도포기 혼재에서 분리). 단 **이미 제출한 프로젝트는 중도포기 여부와 무관하게 보존**한다 — 제출현황 탭의 중도포기자 제출본을 **삭제·비활성화하지 않고** 그대로 표시(`중도포기` 배지로만 식별).
5. **제출현황 탭에 피드백 통합** (별도 피드백 탭 폐지) — 우수 **★ 썸네일 오버레이**, `공개 설정`→**`외부 공개 제한` / `외부 공개 제한 해제`**(사유 입력형, v1.5):
   - 필터 `전체`/`피드백 전`/`피드백 완료`, 제출본 썸네일 위 `피드백 완료/전` 태그
   - 카드 클릭 → 제출본 내용 + **하단 피드백 등록·수정**, `우수 마크` · **`외부 공개 제한`(사유 입력)** 액션. 문제 설명 입력은 **마크다운 에디터**(툴바+미리보기)
   - 중도포기자 제출본도 **동등하게 노출**(흐림·잠금 없음), `중도포기` 배지만 부가(v1.11)

## 8. 알림 — 이번 라운드 = 슬랙 live-class-alert 단일 (생성 실패 2건만)

> **스코프 축소 (v1.6.1, 2026-06-09 / POL-CR-01 v1.3 §7 정합)**: 본 라운드 알림은 **슬랙 `live-class-alert` 1채널**, **AI 노트 생성 실패 · 학습퀴즈 생성 실패 2개 이벤트만** 구현한다. 직전까지의 4채널·다중 이벤트 매트릭스(캠프파이어 운영/매니저 알림·학생 개별 DM 등)는 **차기 범위로 보류**한다(§8.3). 인박스·토스트 등 별도 인앱 알림도 사용하지 않는다.
> 직전 4채널 설계 전문은 아카이브 스냅샷(`prd/archive/PRD-classroom-detail-v1.2-snapshot-2026-06-09.md` §8)에 보존한다.

### 8.1 채널 (본 라운드 단일)

| 채널 | 대상 | 용도 |
|---|---|---|
| **슬랙 "live-class-alert"** | 매니저 (멋사 내부) | **콘텐츠 생성 실패 알림 전용** (AI 노트 / 학습퀴즈) |

> 슬랙 `live-class-alert` 수신 대상은 **캠프파이어 도메인 권한(매니저)** 기준이다. 클래스룸 내 권한(학생/매니저 2종)과 구분된다 (§1).

### 8.2 알림 매트릭스 (본 라운드)

| 이벤트 | 채널 | 발송 방식 / 비고 |
|---|---|---|
| **AI 노트 생성 실패(미생성 오류)** | 슬랙 live-class-alert | **자동** · 멋사 내부 매니저 · 학생 비노출. 메시지에 수업명·대상 일자·발생 시각 포함 |
| **학습퀴즈 생성 실패(미생성 오류)** | 슬랙 live-class-alert | **자동** · 멋사 내부 매니저 · 학생 비노출. 그날 미발행과 동일 처리, 매니저뷰에서 즉시 재생성(§4.2 D·§1.1) |

### 8.3 차기 범위로 보류 (이번 라운드 미구현)

아래는 직전 4채널 매트릭스의 항목으로, **설계만 보존**하고 본 라운드에서는 구현하지 않는다. (전체 설계는 아카이브 스냅샷 §8 참조)

| 보류 이벤트 | 기존 설계 채널 (차기 검토) |
|---|---|
| AI 노트 생성 완료 | 캠프파이어 운영 알림 (학생+매니저) |
| 퀴즈 발행 (default 08:30, 휴일 제외) | 캠프파이어 운영 알림 (학생 안내) |
| 퀴즈 미응시 | (없음 — 미응시 명단 탭으로 확인, 기존 결정 유지) |
| 보충 퀴즈 발행 | (없음 — 학생이 직접 생성, 기존 결정 유지) |
| 실습 발행 | 캠프파이어 운영 알림 + (옵션) 매니저 등록 채널 |
| 실습 채점 완료 | 학생 개별 DM (채점된 경우만) |
| TIL 3일 연속 미작성 | 캠프파이어 매니저 알림 |
| 프로젝트 제출 / 외부 발행 ON | 캠프파이어 매니저 알림 / 슬랙 live-class-alert 추가 |
| 프로젝트 외부 공개 제한 (사유) | 학생 개별 DM + 캠프파이어 매니저 알림 |
| 매니저 수신 채널 선택 옵션 | 4채널 중 본인 수신 채널 선택 (기본 매니저 알림) |

> **흐름표 정합**: §4 기능 흐름표·공통 UI 표에 남아 있는 **"학생 알림(옵션)" · "캠프파이어 공지(옵션)"** 표기(예: 퀴즈 발행 §4.2, 실습 발행/채점 §4.3·공통 UI)는 위 §8.3 보류 채널에 해당한다. **본 라운드에서는 발행·저장만 수행하고 해당 알림은 발송하지 않는다**(슬랙 생성 실패 2건 제외). 차기 라운드에서 채널 복원 시 함께 활성화한다.

## 9. 정책 확정 사항

> 더 이상 합의 필요 항목 없음. §1~§4 디테일에 맞춰 정렬.

| 항목 | 확정 내용 |
|---|---|
| 클래스룸 권한 | **학생 / 매니저 2종**으로만 운영. 캠프파이어·Admin은 별도 4종 권한 운영 (§1) |
| 오답노트 자가 등록 | **불가**. 오답은 퀴즈 응시 시 자동 누적만 |
| 오답노트 액션 | **`메모` · `책갈피` 두 가지만**. 다시 풀기 액션 없음 — 오답은 다시 푼다고 정답으로 전환되지 않음 |
| 오답노트 ↔ 보충 퀴즈 (v1.8) | **통합**. 오답노트는 **강의퀴즈+보충퀴즈 오답**을 함께 누적(출처 필터 제공). 다시 풀기 액션 없음(정답 전환 X)은 유지 |
| 위험군 임계치 | **별도 라벨 X**. 히트맵에서 회색으로 자연스럽게 식별 (향후 Admin 대시보드 고도화 별도 검토) |
| 알림 채널 정책 (v1.6.1 축소) | **본 라운드는 슬랙 `live-class-alert` 단일 채널**, **AI 노트·학습퀴즈 생성 실패 2건만 자동 발송**(학생 비노출)(§8). 4채널 매트릭스·매니저 채널 선택 등은 §8.3 차기 범위로 보류 |
| 마크다운 복사 메타데이터 | **미포함**. 본문만 복사 |
| 마이페이지 통합 위젯 | **별도로 제공하지 않음**. 본 정책 범위 내에서는 만들지 않음 |
| 발행된 퀴즈 수정 | **발행 이후 텍스트만 수정 가능**. 정답·보기 번호는 잠금 |
| 메뉴명 (v1.4) | `AI 퀴즈` → **`학습퀴즈`**, 일일 `오늘의 퀴즈` → **`학습퀴즈`** 통일. AI 생성 액션(`AI 퀴즈 생성`·`AI 문항 생성`)은 라벨 유지 |
| 퀴즈 자동 발행 | **default 08:30, 휴일 제외, 다음 수업일에 진행**. 자동 1세트 발행(추가 발행은 매니저, 하루 최대 20개). 생성 실패는 학생 비노출·매니저만+즉시 재생성 |
| 학습퀴즈 자동 생성 기준 (v1.4) | **AI 노트가 있는 가장 최근 학습일의 모든 노트** 기준으로 생성 (하루 노트 여러 개면 합산) |
| 학습퀴즈 소요시간 (v1.9) | 문항별 **평균 소요시간(난이도 지표)** · **학생별 소요시간**은 **매니저뷰 진단 전용**. **학생뷰에는 소요시간을 일절 표시하지 않음**(응시 중·결과 화면·과거 리스트·보충퀴즈 결과 모두 — v1.8 "결과 화면 표시" 번복). 목표 15분 표기는 v1.8에서 제거 |
| 퀴즈 발행 폼 빈 칸 검증 (v1.9) | 매니저 `임시저장`·`예약발행`·`즉시발행` **세 액션 모두** 빈 필드(퀴즈 제목·문제·보기·정답·해설) 존재 시 **실행 차단 + 인라인 에러** — "아직 입력하지 않은 칸이 있어요. 모든 칸을 채워주세요" |

| 실습 채점 리마인더 | **없음**. 채점 의무 X. 제출 유무만 자동 집계·표시 |

| 실습 발행 후 수정 표기 | 수정 시 **최근 수정 시간 + `수정됨` 배지** 노출 |
| 첨부파일 용량 | **이미지·파일 30MB까지** (실습·프로젝트 공통) |
| 문항 유형 | **객관식만**. OX·단답 도입 없음 |

| 프로젝트 외부 발행 기본값 | **OFF**. 학생이 명시적으로 토글 ON 해야 외부 발행 링크 생성 |

| 학습퀴즈 매니저뷰 중도포기자 집계 (v1.12) | **발행본 상세 3탭·발행 퀴즈 리스트 인원 집계 = `퀴즈 생성 시점` 기준 재적생**(중도포기자 제외). **생성 후 중도포기자는 응시 점수 보존**(`중도포기` 배지로만 식별, 흐림·잠금 없음), **생성 전 중도포기자는 제외**(분모·명단·미응시 미포함). 발행본 상세 상단 `퀴즈 생성 시점 기준 재적생` 안내 + **중도포기자는 출결현황에서 확인** 가이드. 보충 사용현황 히트맵은 누적 뷰라 제외 |
| 매니저 보충 히트맵 풀이완료 집계 (v1.13) | **보충 퀴즈 사용현황 히트맵 강도·셀 클릭 상세 = `풀이가 완료된(제출된)` 보충 세트만** 집계. 학생이 **출제만 하고 풀지 않은 세트는 미포함**, 집계 기준일 = **그 세트를 푼 날짜**. (프로토타입 `SUPP_SOLVED_DAILY`+`openMgrSuppDetail` solved 필터로 기동작 — 정책 명문화) |
