## Story Context

- SSOT: `2026-08-03_훈련평가-재평가-문항-불러오기-기획서.md`(기능정의서 v1.6, FR-001 동일 원본 재선택 시 모달 재노출·FR-007 0건 원본 시 [문항 불러오기] 비활성 확정 반영)
- 대상 기능: 재평가 등록(신규/수정) 화면의 '평가 시험' 필드에서 원본 평가를 선택하면 선택 모달([문항 불러오기](주 버튼) / [불러오지 않고 직접 작성] / 취소)이 노출된다(FR-001, FR-005, FR-006 — 자동 불러오기 폐기, 동일 원본 재선택 시에도 모달 재노출). 기존 문항이 있는 상태에서는 같은 모달에 대체 경고가 병기되며(FR-005), 빈 상태에서는 경고 없이 동일 모달이 노출된다(FR-006). 원본 문항이 0개인 경우 모달에 문항 없음 안내가 노출되고 [문항 불러오기]는 비활성 처리되어 [불러오지 않고 직접 작성]·취소만 선택 가능하다(FR-007). [문항 불러오기] 선택 시에만 조회·로딩·문항 교체가 진행되고(FR-001~FR-003, FR-011), 능력명은 [문항 불러오기]·[불러오지 않고 직접 작성] 어느 쪽을 선택해도 자동 입력되며 취소 시에만 제외된다(FR-004). 평가기간 시작(제출 0건 포함) 또는 응시 이력 존재 시 선택 모달 자체가 노출되지 않고 불러오기·교체가 차단된다(FR-010, 진입·저장 양 시점 검증).
- 화면 ID 표기: 화면정의서(v1.6, `2026-08-03_훈련평가-재평가-문항-불러오기-화면정의서.md`) 확정에 따라 화면 ID는 SC-201(재평가 등록/수정 화면, 단일 화면)이며, 특정 요소 동작을 검증하는 AC는 요소 ID(SC-201-01~10)까지 표기한다. 화면 수준 동작(이탈 경로 등 요소 ID가 배정되지 않은 항목)은 SC-201로만 표기한다. SSOT v1.5 정책 개정(선택 모달 도입)과 SSOT v1.6 보강(동일 원본 재선택 시 모달 재노출, 0건 원본 시 [문항 불러오기] 비활성)은 화면정의서 v1.6에서 SC-201-03·SC-201-04에 확정 반영되어 있다.
- 검증 범위: 노출 여부·활성/비활성 조건·데이터 반영 시점만 검증 대상이다. 안내 문구·에러 메시지·버튼 배치 등 워딩·레이아웃은 화면 설계 영역(SSOT §10)이며 본 인수기준 범위 밖이다.
- TC(테스트케이스) 표기: 이번 위임 범위는 AC 작성까지다. TC ID(TC-###)는 본 산출물에 포함하지 않으며, 후속 위임 시 AC→TC 순으로 별도 작성하고 커버리지 표(FR×AC×TC)를 붙인다. 아래 각 AC는 연결 FR ID와 화면 ID만 표기한다.
- 정책 개정 반영(SSOT v1.5): 자동 불러오기가 폐기되고 선택 모달 방식으로 전환됨에 따라 AC-001(원본 선택 즉시 자동 로딩)·AC-002(빈 상태 모달 없이 즉시 로딩)·AC-010~012(별도 덮어쓰기 모달)를 선택 모달 기준으로 전면 개정했다. [불러오지 않고 직접 작성] 선택지 검증을 위한 AC-025를 신설했다. 조회·로딩·실패·차단·연타 동작 자체(FR-002·FR-003·FR-009·FR-010·FR-011)는 변경되지 않았으며, 트리거 시점만 "드롭다운 선택 즉시"에서 "선택 모달의 [문항 불러오기] 클릭 시"로 조정되어 관련 AC(AC-003·006·008·013·015·016·017·022)의 Given/When 표현을 정합화했다.
- 정책 보강 반영(SSOT v1.6): FR-007이 "0건 원본은 모달에서 [문항 불러오기] 비활성"으로 확정되어, 기존 AC-009의 Given("불러오기를 실행한 상태")이 도달 불가능한 전제가 되었다. AC-009를 "[불러오지 않고 직접 작성]으로 진행해 빈 편집기 상태" 기준으로 개정하고 화면 ID를 SC-201-04로 변경했다. 0건 원본 선택 시 모달 내 안내·비활성 자체를 검증하는 AC-026(FR-007), 동일 원본 재선택 시 모달 재노출을 검증하는 AC-027(FR-001)을 신설했다.
- SSOT §9에 남아있는 나머지 미결(FR-002 임시저장 없음 전제 확인)은 AC-014에 계속 표기했다.

## Happy Path

### AC-001: 원본 선택 시 선택 모달 노출(자동 로딩 폐기)

연결 FR: FR-001 / 화면 ID: SC-201-01

**Given** 강사·매니저가 재평가 등록 화면(신규 등록)의 '평가 시험' 필드가 미선택 상태이다

**When** 유효한 원본 평가를 선택한다

**Then** 문항이 즉시 로딩되지 않고, [문항 불러오기](주 버튼)·[불러오지 않고 직접 작성]·취소 3개 선택지를 제공하는 선택 모달이 노출된다

SSOT v1.5 정책 개정으로 자동 불러오기가 폐기되고 선택 모달 방식으로 전환되었다. 실제 문항 로딩은 사용자가 모달에서 [문항 불러오기]를 클릭한 이후에만 시작된다(후속 AC-011·AC-015 참조).

### AC-002: 문항 편집기 빈 상태에서도 동일 선택 모달 노출(대체 경고만 미노출)

연결 FR: FR-006 / 화면 ID: SC-201-04

**Given** 문항 편집기에 문항이 하나도 없는 상태(신규 등록, 아직 문항 미추가)이다

**When** '평가 시험'에서 원본 평가를 최초로 선택한다

**Then** 기존 문항 존재 시와 동일한 선택 모달([문항 불러오기]/[불러오지 않고 직접 작성]/취소)이 노출되되, 대체할 기존 문항이 없으므로 대체 경고 문구는 노출되지 않는다

SSOT v1.5 정책 개정으로 FR-006이 "빈 상태에서는 모달 없이 즉시 불러오기"에서 "빈 상태에서도 동일 선택 모달 노출(경고만 제외)"로 개정되었다. 화면정의서 v1.6 SC-201-04에서 본 개정이 확정 반영되어 상충 없음을 확인했다.

### AC-003: 문항 전체와 능력명이 복사되고, 평가 제목·평가기간·대상자는 복사되지 않음

연결 FR: FR-004 / 화면 ID: SC-201-06

**Given** 원본 평가에 문항이 1개 이상 존재한다

**When** 선택 모달에서 [문항 불러오기]를 선택해 문항 불러오기가 완료된다

**Then** 질문명·보조 설명·문제 유형·보기·정답·해설·배점·문항 순서는 원본 값으로 채워지고, 능력명 필드는 원본 값으로 자동 입력되며 편집 가능한 상태로 유지된다. 평가 제목·평가 시작일~종료일·대상자 필드는 값이 채워지지 않은 채 유지된다(사용자가 신규로 입력해야 하는 상태로 남는다)

복사 범위(문항 전체 + 능력명 복사, 평가 제목·평가기간·대상자 미복사)는 SSOT v1.4 사용자 확정으로 승인 완료되었다. 이전 버전의 `[결정 필요]` 표기는 해소되었다.

### AC-004: 저장 전에는 서버 미반영 초안 상태로만 존재

연결 FR: FR-002, FR-003 / 화면 ID: SC-201-06

**Given** 문항 불러오기가 완료되어 문항 편집기에 초안이 채워진 상태이다

**When** 사용자가 [저장하기]를 클릭하지 않은 상태에서 화면을 유지한다

**Then** 불러온 문항은 서버에 반영되지 않은 편집 가능한 초안으로만 존재한다

### AC-005: 저장 후 원본 평가와 재평가 문항은 상호 독립(스냅샷)

연결 FR: FR-003 / 화면 ID: SC-201-06

**Given** 재평가가 저장 완료되어 문항이 스냅샷으로 확정된 상태이다

**When** (a) 원본 평가의 문항을 수정·삭제하거나 (b) 저장된 재평가의 문항을 수정한다

**Then** (a) 원본 변경은 이미 저장된 재평가 문항에 영향을 주지 않고, (b) 재평가 문항 수정은 원본 평가에 영향을 주지 않는다(양방향 참조·연결 관계 없음)

### AC-006: 필수값 검증은 저장 시점에만 수행

연결 FR: FR-008 / 화면 ID: SC-201-09

**Given** 원본 평가에 필수값이 누락된 문항이 존재한다

**When** 선택 모달에서 [문항 불러오기]를 선택해 해당 원본으로 문항을 불러온다

**Then** 로딩은 그대로 완료되고 로딩 시점에는 에러가 표시되지 않는다. 이후 사용자가 [저장하기]를 클릭하면 해당 문항에 에러가 표시되고 저장이 차단된다

### AC-007: 삭제된 평가는 '평가 시험' 드롭다운에 노출되지 않음

연결 FR: FR-009 / 화면 ID: SC-201

**Given** 특정 평가가 삭제(비유효화)된 상태이다

**When** 재평가 등록 화면에서 '평가 시험' 드롭다운을 연다

**Then** 삭제된 평가는 목록에 노출되지 않는다(기존 로직 준용, 신규 조회 스코프 아님)

### AC-008: 문제 유형별 복사 대상 필드 차등 적용

연결 FR: FR-004(§4.2) / 화면 ID: SC-201-06

**Given** 원본 평가에 객관식 문항과 주관식 문항이 혼재한다

**When** 선택 모달에서 [문항 불러오기]를 선택해 문항 불러오기를 실행한다

**Then** 객관식 문항은 질문명·보조 설명·보기(최대 5개)·정답(보기 중 선택값)·해설·배점이 복사되고, 주관식 문항은 질문명·보조 설명·정답(텍스트)·해설·배점이 복사된다(주관식 문항에는 보기 필드가 생성되지 않는다)

### AC-023: 저장 성공 시 문항 스냅샷 확정 및 목록 반영

연결 FR: FR-002, FR-003 / 화면 ID: SC-201-09

**Given** 문항 불러오기가 완료되고 사용자가 문항 점검·수정을 마친 상태이다

**When** 사용자가 [저장하기]를 클릭하고 필수값 검증을 통과한다

**Then** 문항 N건이 스냅샷으로 서버에 최종 저장되고, 훈련평가 목록 화면에서 해당 재평가가 저장된 상태로 조회된다

훈련평가 목록 화면은 SC-201(재평가 등록/수정 화면) 범위 밖의 별도 화면이며, 이 문서는 목록 화면에서의 조회 가능 여부(관찰 가능한 결과)만 검증 대상으로 삼는다. 목록 화면 자체의 요소 ID는 본 인수기준 범위 밖이다.

## Edge Cases

### AC-009: 원본 문항 0개 시 [불러오지 않고 직접 작성]으로 진행한 빈 편집기 상태에서 저장 시도 시 거부

연결 FR: FR-007 / 화면 ID: SC-201-04

**Given** 원본 평가에 등록된 문항이 0개인 상태에서, 사용자가 선택 모달의 [불러오지 않고 직접 작성]을 클릭해 문항 편집기가 빈 상태로 유지되고 있다([문항 불러오기]는 SSOT v1.6 FR-007 확정에 따라 비활성 처리되어 선택할 수 없다)

**When** 사용자가 문항을 추가하지 않은 채 [저장하기]를 클릭한다

**Then** 저장이 거부되고 최소 1문항이 필요하다는 에러가 표시되며, 재평가는 저장되지 않는다

최소 문항 수 하한(1문항 미만 저장 불허)은 SSOT v1.4 사용자 확정으로 확정되었다. 단, 기존 평가 등록 화면의 저장 검증 룰에 별도의 하한이 이미 있는 경우 그 기존 룰이 우선 적용된다(개발 검토 시 확인). SSOT v1.6에서 FR-007에 "0건 원본은 모달에서 [문항 불러오기] 비활성" 조항이 추가되어, 종전 Given("불러오기를 실행한 상태")은 도달 불가능한 전제가 되었으므로 위와 같이 개정했다.

### AC-026: 원본 문항 0개 선택 시 모달 내 문항 없음 안내 및 [문항 불러오기] 비활성

연결 FR: FR-007 / 화면 ID: SC-201-03·SC-201-04

**Given** 사용자가 등록된 문항이 0개인 원본 평가를 '평가 시험'에서 선택한다(문항 편집기의 기존 문항 유무와 무관 — 두 경로 모두 검증)

**When** 선택 모달이 노출된다

**Then** 모달에 문항이 없음을 알리는 안내가 표시되고 [문항 불러오기] 버튼은 비활성(선택 불가) 처리되며, [불러오지 않고 직접 작성]과 취소만 선택 가능하다

본 AC는 SSOT v1.6 FR-007 확정("0건 원본은 모달에서 [문항 불러오기] 비활성")에 근거해 신설했다. 화면정의서 v1.6 SC-201-04에 동일 조항이 확정 정의되어 있다.

### AC-010: 기존 문항 존재 상태에서 원본 재선택 시 선택 모달에 대체 경고 병기

연결 FR: FR-005 / 화면 ID: SC-201-03

**Given** 문항 편집기에 1개 이상의 문항이 이미 존재한다(신규 작성 중 최소 1개 추가 상태, 또는 평가기간 시작 전·응시 이력 없는 저장된 재평가를 열람한 상태)

**When** '평가 시험' 값을 다른 원본으로 변경한다

**Then** 선택 모달([문항 불러오기]/[불러오지 않고 직접 작성]/취소)이 노출되며, 기존 문항이 대체된다는 경고 문구가 함께 표시된다

본 AC는 SSOT v1.5 정책 개정으로 기존 "덮어쓰기 확인 모달"이 별도 모달이 아니라 선택 모달에 대체 경고를 병기하는 방식으로 통합된 것을 반영했다. 화면정의서 v1.6 SC-201-03에서 본 개정이 확정 반영되어 상충 없음을 확인했다.

### AC-011: 선택 모달에서 [문항 불러오기] 선택 시 조회 성공 시점에 일괄 교체

연결 FR: FR-005 / 화면 ID: SC-201-03

**Given** 기존 문항 존재로 대체 경고가 병기된 선택 모달이 노출된 상태이다

**When** 사용자가 [문항 불러오기]를 클릭한다

**Then** 신규 원본 문항 조회가 성공한 시점에 기존 문항 전체가 삭제되고 신규 원본 문항으로 교체된다(조회 성공 이전에는 기존 문항이 선삭제되지 않는다)

### AC-012: 선택 모달 취소 시 선택값·문항·능력명 원복

연결 FR: FR-005 / 화면 ID: SC-201-03

**Given** 선택 모달이 노출된 상태이다(대체 경고 병기 여부와 무관)

**When** 사용자가 취소를 클릭한다

**Then** '평가 시험' 선택값은 직전 상태로 되돌아가고, 기존 문항과 능력명 필드는 변경 없이 그대로 유지된다

### AC-025: [불러오지 않고 직접 작성] 선택 시 문항 미로드·기존 문항 유지·능력명 자동 입력

연결 FR: FR-004, FR-005, FR-006 / 화면 ID: SC-201-03, SC-201-04

**Given** 원본 평가 선택으로 선택 모달이 노출된 상태이다(기존 문항 유무·대체 경고 병기 여부와 무관)

**When** 사용자가 [불러오지 않고 직접 작성]을 클릭한다

**Then** 문항은 조회·로드되지 않고 기존에 작성돼 있던 문항(있었다면)은 변경 없이 그대로 유지되며, 능력명 필드만 원본 평가의 능력명 값으로 자동 입력된다(편집 가능한 상태)

본 AC는 SSOT v1.5 사용자 확정("능력명은 어느 선택이든 자동 입력, 취소 시 제외")에 근거해 신설했다. 화면정의서 v1.6 SC-201-03·SC-201-04 결과 칸에 [불러오지 않고 직접 작성] 선택지 동작(문항 유지, 능력명 자동 입력)이 확정 정의되어 있어 상충 없음을 확인했다.

### AC-027: 동일 원본 재선택 시에도 선택 모달 재노출

연결 FR: FR-001 / 화면 ID: SC-201-03, SC-201-04

**Given** '평가 시험'에 이미 특정 원본 평가가 선택되어 있는 상태이다

**When** 사용자가 동일한 원본 평가를 다시 선택한다

**Then** 선택 모달이 다시 노출된다(이미 선택된 것과 동일한 원본이라는 이유로 모달 노출이 생략되지 않는다)

본 AC는 SSOT v1.6 FR-001 확정("동일한 원본 평가를 다시 선택한 경우에도 선택 모달을 노출한다")에 근거해 신설했다. 화면정의서 v1.6 SC-201-03·SC-201-04 노출 조건에 "최초·재선택 무관(동일 원본 재선택 포함)"이 확정 정의되어 있다.

### AC-013: 응시 이력 존재 시 FR-005(선택 모달) 대신 FR-010(차단)이 우선 적용

연결 FR: FR-005, FR-010 / 화면 ID: SC-201-03, SC-201-10

**Given** 저장된 재평가에 응시 이력이 1건 이상 존재한다

**When** 사용자가 '평가 시험' 원본을 재선택하려 시도한다

**Then** 선택 모달이 노출되지 않고, FR-010에 정의된 차단 동작('평가 시험' UI 비활성 및 안내 문구 노출)이 적용된다

### AC-014: 저장 전 화면 이탈 시 불러온 내용 소실

연결 FR: FR-002 / 화면 ID: SC-201

**Given** 문항 불러오기가 완료되었으나 저장하지 않은 상태이다

**When** 사용자가 저장 없이 화면을 이탈한다(뒤로가기 등)

**Then** 불러온 문항 내용은 소실되며, 재진입 시 원본 선택부터 다시 진행해야 한다

`[확인 필요]` 본 AC는 "재평가 등록 화면에 임시저장 기능이 없다"는 전제(FR-002 근거) 위에서 작성되었다. 이 전제가 실제 스펙과 일치하는지는 SSOT §9 "기존 스펙 조사로 확정 가능" 목록에 미결로 등재되어 있다. 임시저장 기능이 존재하는 것으로 확인되면 본 AC는 폐기 또는 재작성이 필요하다.

## Error States

### AC-015: 문항 조회 중 로딩 상태 노출

연결 FR: FR-011 / 화면 ID: SC-201-02

**Given** 사용자가 선택 모달에서 [문항 불러오기]를 클릭해 문항 조회 요청이 진행 중이다

**When** 조회 응답을 기다리는 동안

**Then** 로딩 상태가 화면에 표시된다

### AC-016: 조회 실패 시 기존 문항 보존 및 드롭다운 선택값 롤백

연결 FR: FR-011 / 화면 ID: SC-201-08

**Given** 사용자가 선택 모달에서 [문항 불러오기]를 클릭해 문항 조회를 요청한 상태이다(대체 경고 병기 여부와 무관)

**When** 문항 조회 API가 실패로 응답한다

**Then** 에러만 노출되고 기존에 작성돼 있던 문항은 그대로 보존되며(문항 교체는 발생하지 않는다), '평가 시험' 드롭다운 선택값은 직전 값으로 롤백된다

### AC-017: 원본 연속 재선택(연타) 시 마지막 선택 1회만 반영

연결 FR: FR-011 / 화면 ID: SC-201-07

**Given** 사용자가 서로 다른 원본 평가에 대해 선택 모달에서 [문항 불러오기]를 연속으로 빠르게 클릭한다

**When** 짧은 시간 내 여러 번의 조회 요청이 발생한다

**Then** 마지막 선택값을 기준으로 1회만 최종 조회가 수행되고 문항 편집기에 반영된다(중간 선택에 대한 조회·반영은 발생하지 않는다)

### AC-018: 응시 이력 존재 시 문항 불러오기·교체 자체를 차단

연결 FR: FR-010 / 화면 ID: SC-201-10

**Given** 이미 저장된 재평가 수정 화면이며, 해당 재평가에 응시 이력(답안 제출)이 1건 이상 존재한다

**When** 사용자가 '평가 시험' 값을 변경하거나 문항 불러오기를 시도한다

**Then** 문항 불러오기·교체가 차단되고 안내 문구만 노출되며, 실제 문항 데이터(내용·순서 포함)는 변경되지 않는다

### AC-019: 차단 상태에서 '평가 시험' UI 비활성 처리 및 사유 안내

연결 FR: FR-010 / 화면 ID: SC-201-10

**Given** 이미 저장된 재평가 수정 화면이며 응시 이력이 1건 이상 존재한다

**When** 해당 재평가 수정 화면에 진입한다

**Then** '평가 시험' 변경 UI는 비활성(disabled) 상태로 표시되고, 비활성 사유 안내 문구가 함께 노출된다

### AC-020: 차단 시 신규 재평가 생성 우회 안내 노출

연결 FR: FR-010 / 화면 ID: SC-201-10

**Given** 응시 이력 존재로 문항 불러오기·교체가 차단된 상태이다

**When** 사용자가 해당 화면의 안내 영역을 확인한다

**Then** 문항 변경이 필요한 경우 신규 재평가 생성으로 우회하라는 안내가 노출된다

### AC-024: 저장 시점 차단 대상 재검증 — 진입 이후 차단 대상이 된 재평가의 저장 거부

연결 FR: FR-010 / 화면 ID: SC-201-09

**Given** 사용자가 평가기간 시작 전(응시 이력 없음) 상태에서 재평가 수정 화면에 진입해 문항 불러오기·편집을 진행하고 있었으나, 저장 요청 이전에 해당 재평가의 평가기간이 시작되었다(응시 이력 발생 여부와 무관하게 제출 0건 포함, FR-010 확장 차단 조건 충족)

**When** 사용자가 [저장하기]를 클릭한다

**Then** 저장 시점 재검증에서 차단 조건(평가기간 시작 이후) 충족이 확인되어 저장이 거부되고 안내 문구가 노출되며, 편집 중이던 문항 변경 내용은 서버에 반영되지 않는다

본 AC는 SSOT v1.3 FR-010에 신설된 "진입·저장 양 시점 검증" 조항과 SSOT v1.4에서 확장된 차단 조건(평가기간 시작 이후, 제출 0건 포함)을 근거로 작성했다. 화면정의서 SC-201-09 예외②가 이 저장 시점 재검증 동작(진입 시점에는 차단 대상이 아니었더라도 저장 요청 시점에 차단 대상으로 확인되면 저장 거부)을 정의하고 있어 요소 ID를 SC-201-09로 확정했다.

## Non-Functional / 정책 경계 조건

### AC-021: 평가기간 시작 이후(제출 0건 포함) 상태의 문항 불러오기·교체 차단

연결 FR: FR-010(§4.1) / 화면 ID: SC-201-10

**Given** 저장된 재평가의 평가기간이 시작되었으며 응시자의 답안 제출 건수가 0건인 상태이다

**When** 사용자가 원본을 재선택하거나 문항 불러오기를 시도한다

**Then** FR-010과 동일하게 문항 불러오기·교체가 차단되고 '평가 시험' UI가 비활성(disabled) 처리되며 비활성 사유 안내 문구가 노출된다

본 AC는 SSOT v1.4 사용자 확정으로 "평가기간이 시작된 재평가(제출 0건 포함)"부터 응시 이력 존재로 간주해 차단 대상에 포함하는 것으로 확정되어 작성했다. 이전 버전의 `[확인 필요]`·`[결정 필요]` 표기는 해소되었다. §4.1 상태별 허용 여부 표는 SSOT v1.4에서 본 확정에 맞춰 갱신 완료되었다.

### AC-022: 문항 교체는 원본 조회 성공 시점에만 발생(선삭제 금지 원칙의 일관 적용)

연결 FR: FR-005, FR-011 / 화면 ID: SC-201-03, SC-201-07, SC-201-08

**Given** 선택 모달에서 [문항 불러오기] 클릭, 연속 재선택(연타), 조회 실패 중 어느 트리거이든 원본 문항 교체가 진행될 수 있는 상황이다

**When** 위 트리거가 발생한다

**Then** 어떤 트리거에서도 기존 문항의 삭제는 신규 원본 문항 조회가 성공적으로 완료된 시점에만 일괄 수행되며, 조회가 완료되지 않았거나 실패한 경우에는 기존 문항이 부분적으로도 삭제되지 않는다

## Notes

- 본 산출물의 범위(AC 작성)만 다루며, TC(테스트케이스)·커버리지 표(FR×AC×TC)·엣지케이스 신규 발굴은 포함하지 않는다. 엣지케이스 발굴은 별도 담당 영역이며, 해당 산출물이 존재할 경우 TC 작성 단계에서 통합한다.
- 문구·레이아웃 워딩 검증은 범위 밖이며, 위 AC는 노출 여부·활성/비활성 여부·데이터 반영 시점만 검증한다.
- SSOT §8 제외 범위(평가↔평가 문항 복제, 문항 은행/템플릿, 다른 기수 간 복제, 원본 평가 삭제 정책 변경, 응시 이력 존재 시 개별 문항 수동 편집 제어)에 대한 AC는 작성하지 않았다(범위 확장 금지).
