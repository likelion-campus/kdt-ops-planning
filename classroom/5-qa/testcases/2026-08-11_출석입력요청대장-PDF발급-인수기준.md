## 1. 인수기준(AC)

### 1.1 상태별 카드·버튼 노출

#### AC-001 상태=접수 시 카드·버튼 노출
**Given** 공결 신청 건의 상태가 `접수`이고 운영자가 AS-001 상세 화면에 진입했을 때
**When** 화면이 로드되면
**Then** ①훈련생 / ②훈련 과정 정보 / ③공결 신청 내역(공결일·신청일 조회 전용) / ⑤첨부파일 카드는 노출되고, ④외출/귀원 시간 카드(입실시간·퇴실시간 — 훈련시간 입력 필드는 §10-12 번복으로 삭제되어 이 카드에 없음, AC-008 참고)는 미노출되며, 사이드바 버튼은 [목록으로] / [확인중으로 변경하기] 2개만 노출된다.
근거: 기획서 §4-1 상태별 화면 노출 및 사이드바 버튼 구성 표, AS-001 "가. 상태 = 접수"
상태: 정상

#### AC-002 상태=확인중 시 카드·버튼 노출
**Given** 공결 신청 건의 상태가 `확인중`일 때
**When** AS-001 상세 화면에 진입하면
**Then** ①②⑤ 카드는 조회 전용으로 노출되고, ③공결 신청 내역 카드는 공결일·신청일만 편집 가능(값이 신청 원본과 달라지면 항목 옆에 "신청 원본: YYYY-MM-DD" 병기, 신청 항목·상세 사유·추가 사유는 조회 전용 유지 — AC-031 참고)하며, ④외출/귀원 시간 카드(입실시간·퇴실시간 — 훈련시간 필드는 §10-12 번복으로 이 카드에 없음)는 노출·편집 가능 상태로 전환된다. 사이드바 버튼은 [목록으로] / [저장하기] / [완료로 변경하기] 3개가 노출된다.
근거: 기획서 §4-1, AS-001 "나. 상태 = 확인중"
상태: 정상

#### AC-003 상태=완료 시 카드·버튼 노출
**Given** 공결 신청 건의 상태가 `완료`일 때
**When** AS-001 상세 화면에 진입하면
**Then** ①②⑤ 카드는 조회 전용으로 노출되고, ③공결 신청 내역 카드(공결일·신청일 포함)는 잠금(조회 전용)이며, ④외출/귀원 시간 카드는 노출되지만 편집 불가(조회 전용)이다. 사이드바 버튼은 [목록으로]와 (권한 보유 시) [출석입력요청대장 PDF 다운로드]만 노출된다.
근거: 기획서 §4-1, AS-001 "다. 상태 = 완료"
상태: 정상 (PDF 버튼 노출의 권한 조건은 1.5 참고)

### 1.2 상태 전이 순차성

#### AC-004 접수 → 확인중 전이
**Given** 상태가 `접수`인 공결 신청 건에서
**When** 운영자가 [확인중으로 변경하기] 버튼을 클릭하면
**Then** 상태가 `확인중`으로 전환되고 ③공결 신청 내역 카드의 공결일·신청일이 편집 가능 상태로 전환되며, ④외출/귀원 시간 카드가 노출·편집 가능 상태로 바뀐다. 사이드바 상태 표시가 `{훈련생명}님은 ●확인중 상태입니다.`로 갱신된다.
근거: 기획서 §4-1 상태 전이 다이어그램, AS-001 화면 흐름도
상태: 정상

#### AC-005 확인중 → 완료 전이
**Given** 상태가 `확인중`이고 ③공결 신청 내역 카드(공결일·신청일)와 ④외출/귀원 시간 카드(입실시간·퇴실시간)의 값이 저장되어 있으며, ②훈련 과정 정보 카드의 훈련 시간 연동값이 존재할 때(§10-12 번복 — AC-008 참고)
**When** 운영자가 [완료로 변경하기] 버튼을 클릭하면
**Then** 상태가 `완료`로 전환되고, 저장된 값(③공결일·신청일, ④외출·귀원 시간)과 ②카드 연동 훈련시간을 기준으로 데이터가 잠금 처리된다.
근거: 기획서 §4-1, AS-001 "나. 상태 = 확인중" 버튼 표
상태: 정상

#### AC-006 단계 건너뛰기·역방향 전환 불가
**Given** 공결 신청 건이 임의의 상태(접수/확인중/완료)에 있을 때
**When** 사이드바 버튼 구성을 확인하면
**Then** 접수 상태에는 확인중을 건너뛰고 완료로 바로 전환하는 버튼이 존재하지 않고, 확인중·완료 상태에는 이전 상태로 되돌리는 버튼이 존재하지 않는다. 상태 전이는 접수 → 확인중 → 완료 순으로만 가능하다.
근거: 기획서 §4-1 "접수 → 확인중 → 완료 순으로만 전환 가능. 단계 건너뛰기 불가, 역방향 전환 불가"
상태: 정상
> UI 레벨 검증만 해당 — 서버 레벨 전이 강제는 엣지케이스 문서 EC-007(미정) 참고

### 1.3 훈련시간 검증 (§10-12 번복 — 2026-08-11 훈련 과정 정보 연동값 자동 매핑으로 전환)

#### AC-007 (무효화) 훈련시간 미입력 시 저장 차단 — §10-12 번복으로 시나리오 소멸

근거: `docs/decisions.md` 2026-08-11 "훈련시간 수기 입력 삭제"(§10-12 번복)
상태: 무효화(§10-12 번복) — 대체 검증은 AC-008 참고

#### AC-008 훈련 시간 연동값 부재 시 완료 전환·PDF 발급 차단 (§10-12 번복 반영)
**Given** ②훈련 과정 정보 카드의 훈련 시간(부트캠프 훈련 관리 연동값)이 비어 있는 공결 신청 건이 `확인중` 상태일 때
**When** 운영자가 [완료로 변경하기] 버튼을 클릭하면
**Then** 완료 전환이 차단되고 원천(훈련 관리) 등록 안내가 노출되며 상태는 `확인중`으로 유지된다. [확인 필요] 이미 `완료` 상태인 건에서 이후 ②카드 연동값이 사라지는 경우 PDF 발급 시점에도 동일하게 차단되는지(스냅샷 고정 vs 실시간 재조회)는 기획서 §11 순서5(상류 데이터 연동 방식, [개발 검토 필요])가 미확정이라 판정 보류.
근거: `docs/decisions.md` 2026-08-11 "훈련시간 수기 입력 삭제"(§10-12 번복), 기획서 §11 순서5
상태: 정상 (PDF 발급 시점 재검증 여부는 [확인 필요] — §11 순서5 확정 후 판정)

### 1.4 완료 전환 후 데이터 잠금

#### AC-009 완료 전환 후 전 카드 데이터 잠금
**Given** 공결 신청 건이 `완료` 상태로 전환되었을 때
**When** 운영자가 AS-001 상세 화면의 ①~⑤ 카드(③공결 신청 내역 카드의 공결일·신청일, ④외출/귀원 시간 카드의 입실·퇴실시간 포함 — 훈련시간은 §10-12 번복으로 ②카드 연동값 자동 매핑이라 잠금 대상 입력값이 아님)를 조작하려 시도하면
**Then** 모든 입력 컴포넌트가 조회 전용으로 전환되어 수정이 불가능하다. 상태를 되돌리거나 잠금을 해제하는 UI 경로는 존재하지 않는다.
근거: 기획서 §4-1 데이터 잠금 정책, AS-001 "데이터 잠금 정책"
상태: 정상 (오류 데이터 정정 절차는 §9-5 제외 범위 — 본 AC의 검증 대상 아님)

### 1.14 전제조건 대기 (자산 제공 — §10-1·§10-9)

기획서 §10-1·§10-9는 "차단"이 아니라 개발 착수 시 사용자가 자산(훈련기관명 텍스트·서명 이미지 파일)을 직접 제공하기로 확정되어 "전제조건 대기"로 상태가 바뀌었다. 정책 자체는 확정되었으나 실제 자산 값이 아직 없어 값 검증은 자산 수령 후 실행한다.

#### AC-020 훈련기관명 고정값 인쇄 — 전제조건 대기(자산 제공: 훈련기관명 표기)
**Given** PDF 상단 훈련기관 표기란(`( {훈련기관명} )`)을 출력할 때
**When** PDF가 생성되면
**Then** 사용자가 개발 착수 시 제공하는 멋사 정식 기관 명칭이 그대로 인쇄된다. 실제 텍스트 값(자산)이 아직 전달되지 않아, 값 자체의 정합성 검증은 자산 수령 후 실행한다.
근거: 기획서 §7-1, §10-1(2026-08-03 상태 변경: 자산 제공 대기)
상태: 전제조건 대기(자산 제공: 훈련기관명 표기)

#### AC-022 관리자 서명(⑬) 자동 반영 — 전제조건 대기(자산 제공: 서명 이미지)
**Given** PDF ⑬ 관리자 서명 칸에 사전 등록된 서명 이미지를 자동 반영해야 할 때

근거: 기획서 §5(⑬), §7-3, §10-9(2026-08-03 상태 변경: 자산 제공 대기)
상태: 전제조건 대기(자산 제공: 관리자 서명 이미지)

## 5. 승계된 §10 확인 필요 사항 (AC/TC 대상 외 — 비차단, v1.8 기준)

기획서 v1.8 기준 §10은 총 31건: **확정 8건**(§10-3, 10, 11, 12, 13, 14, 15, 26 — §10-15는 2026-08-11 최종 재확정, 기획서 §7-2·§10 표 동일 확정 반영 확인) / **정책 차단 5건**(§10-6, 20, 21, 25, 29) / **자산 대기 3건**(§10-1, 9, 19 — AC-020·022는 §10-1·9를, AC-018/TC-019는 §10-19를 반영 완료) / **해소 1건**(§10-18, 서식 원본 수령으로 PDF 렌더 착수 차단 해제) / **비차단 14건**. 아래 표는 이 14건의 비차단 항목(§10-31 신규 포함)이다. 이번 QA 산출물의 최소 커버 범위에 명시적으로 포함되지 않아 별도 AC/TC를 만들지 않았다. 임의로 결론 내지 않고 기획서 §10 원문 그대로 승계한다.

> **v1.6~v1.8 델타 반영 이력**: v1.6 — 공결일·신청일이 별도 카드가 아닌 ③공결 신청 내역 카드 인라인 수정(신청 원본 병기)으로 개편, "신청 원본" 병기 검증 AC-031/TC-032 신규 등록. v1.7 — §10-12 번복(훈련시간 수기 입력 삭제, PDF ③은 ②카드 연동값 자동 매핑), AC-007·AC-024(및 TC-008·TC-025) 무효화, AC-008(및 TC-009) 신규 검증 재작성. v1.8 — 카드④ 명칭이 "별지 13호 추가 입력" → **"외출/귀원 시간"**으로 재개명(본 문서 전수 갱신 완료), §10-18 서식 원본 수령으로 PDF 렌더 착수 차단 해제, §10-26 종결(⑩=입실〈외출〉/⑪=퇴실〈귀원〉 확정 — AC-025/TC-026 반영), §10-15가 서식 원본 확인 결과 "번호 1~15 인쇄 + 데이터는 1행만 기재"로 재확정(AC-015·AC-027/TC-016·TC-028 반영, `docs/decisions.md` 2026-08-11 근거).
