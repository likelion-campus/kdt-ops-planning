## 1. 인수기준(AC)

### 1.1 상태별 카드·버튼 노출

#### AC-001 상태=접수 시 카드·버튼 노출
**Given** 공결 신청 건의 상태가 `접수`이고 운영자가 AS-001 상세 화면에 진입했을 때
**When** 화면이 로드되면
**Then** ①훈련생 / ②훈련 과정 정보 / ③공결 신청 내역 / ⑤첨부파일 카드는 노출되고, ④출석입력요청대장 수기 보완 카드는 미노출되며, 사이드바 버튼은 [목록으로] / [확인중으로 변경하기] 2개만 노출된다.
근거: 기획서 §4-1 상태별 화면 노출 및 사이드바 버튼 구성 표, AS-001 "가. 상태 = 접수"
상태: 정상

#### AC-002 상태=확인중 시 카드·버튼 노출
**Given** 공결 신청 건의 상태가 `확인중`일 때
**When** AS-001 상세 화면에 진입하면
**Then** ①②③⑤ 카드는 조회 전용으로 노출되고, ④수기 보완 카드는 노출·편집 가능 상태로 전환되며, 사이드바 버튼은 [목록으로] / [저장하기] / [완료로 변경하기] 3개가 노출된다.
근거: 기획서 §4-1, AS-001 "나. 상태 = 확인중"
상태: 정상

#### AC-003 상태=완료 시 카드·버튼 노출
**Given** 공결 신청 건의 상태가 `완료`일 때
**When** AS-001 상세 화면에 진입하면
**Then** ①②③⑤ 카드는 조회 전용으로 노출되고, ④수기 보완 카드는 노출되지만 편집 불가(조회 전용)이며, 사이드바 버튼은 [목록으로]와 (권한 보유 시) [출석입력요청대장 PDF 다운로드]만 노출된다.
근거: 기획서 §4-1, AS-001 "다. 상태 = 완료"
상태: 정상 (PDF 버튼 노출의 권한 조건은 1.5 참고)

### 1.2 상태 전이 순차성

#### AC-004 접수 → 확인중 전이
**Given** 상태가 `접수`인 공결 신청 건에서
**When** 운영자가 [확인중으로 변경하기] 버튼을 클릭하면
**Then** 상태가 `확인중`으로 전환되고 ④수기 보완 카드가 노출·편집 가능 상태로 바뀌며, 사이드바 상태 표시가 `{훈련생명}님은 ●확인중 상태입니다.`로 갱신된다.
근거: 기획서 §4-1 상태 전이 다이어그램, AS-001 화면 흐름도
상태: 정상

#### AC-005 확인중 → 완료 전이
**Given** 상태가 `확인중`이고 훈련시간을 포함한 수기 보완 값이 저장되어 있을 때
**When** 운영자가 [완료로 변경하기] 버튼을 클릭하면
**Then** 상태가 `완료`로 전환되고, 저장된 수기 보완 값을 기준으로 데이터가 잠금 처리된다.
근거: 기획서 §4-1, AS-001 "나. 상태 = 확인중" 버튼 표
상태: 정상

#### AC-006 단계 건너뛰기·역방향 전환 불가
**Given** 공결 신청 건이 임의의 상태(접수/확인중/완료)에 있을 때
**When** 사이드바 버튼 구성을 확인하면
**Then** 접수 상태에는 확인중을 건너뛰고 완료로 바로 전환하는 버튼이 존재하지 않고, 확인중·완료 상태에는 이전 상태로 되돌리는 버튼이 존재하지 않는다. 상태 전이는 접수 → 확인중 → 완료 순으로만 가능하다.
근거: 기획서 §4-1 "접수 → 확인중 → 완료 순으로만 전환 가능. 단계 건너뛰기 불가, 역방향 전환 불가"
상태: 정상
> UI 레벨 검증만 해당 — 서버 레벨 전이 강제는 엣지케이스 문서 EC-007(미정) 참고

### 1.3 훈련시간 필수 검증

#### AC-007 훈련시간 미입력 시 저장 차단
**Given** 상태가 `확인중`이고 훈련시간 입력값이 빈 값일 때
**When** 운영자가 [저장하기] 버튼을 클릭하면
**Then** 저장이 차단되고 "훈련시간을 입력해 주세요." 에러 문구가 노출되며, 다른 필드(공결일 수정/신청일 수정)가 유효해도 저장은 진행되지 않는다.
근거: 기획서 §4-1 필수 필드 검증 표, AS-001 "나. 상태 = 확인중" 필수 필드 검증 표
상태: 정상

#### AC-008 훈련시간 미입력 시 완료 전환 차단
**Given** 상태가 `확인중`이고 훈련시간 입력값이 빈 값일 때
**When** 운영자가 [완료로 변경하기] 버튼을 클릭하면
**Then** 완료 전환이 차단되고 "훈련시간을 입력해 주세요." 에러 문구가 노출되며 상태는 `확인중`으로 유지된다.
근거: 기획서 §4-1 "훈련시간이 비어있으면 저장 차단"·필수 필드 검증 표, AS-001 [완료로 변경하기] 예외 열
상태: 정상

### 1.4 완료 전환 후 데이터 잠금

#### AC-009 완료 전환 후 전 카드 데이터 잠금
**Given** 공결 신청 건이 `완료` 상태로 전환되었을 때
**When** 운영자가 AS-001 상세 화면의 ①~⑤ 카드(수기 보완 카드 포함: 공결일 수정/신청일 수정/훈련시간/입실·퇴실시간)를 조작하려 시도하면
**Then** 모든 입력 컴포넌트가 조회 전용으로 전환되어 수정이 불가능하다. 상태를 되돌리거나 잠금을 해제하는 UI 경로는 존재하지 않는다.
근거: 기획서 §4-1 데이터 잠금 정책, AS-001 "데이터 잠금 정책"
상태: 정상 (오류 데이터 정정 절차는 §9-5 제외 범위 — 본 AC의 검증 대상 아님)

### 1.5 PDF 발급 조건 (완료 상태 + 유관부서 담당자 권한)

#### AC-010 PDF 다운로드 버튼 노출 및 즉시 다운로드 (완료 + 권한 보유)
**Given** 공결 신청 건이 `완료` 상태이고 로그인한 운영자가 유관부서 담당자 권한을 보유했을 때
**When** AS-001 상세 화면에 진입하면
**Then** [출석입력요청대장 PDF 다운로드] 버튼이 노출되고, 클릭 시 별도 화면 이동 없이 즉시 PDF가 다운로드된다.
근거: 기획서 §3-3, §4-1 상태별 버튼 표, AS-001 "다. 상태 = 완료" 사이드바 버튼 표
상태: 정상 (발급 대상 신청 항목 범위는 §10-11 확정 — 신청 항목 무관 전체 대상. AC-023 참고)

#### AC-011 PDF 다운로드 버튼 미노출 (완료 + 권한 미보유)
**Given** 공결 신청 건이 `완료` 상태이고 로그인한 운영자가 유관부서 담당자 권한을 보유하지 않았을 때
**When** AS-001 상세 화면에 진입하면
**Then** [출석입력요청대장 PDF 다운로드] 버튼이 화면에 노출되지 않는다(비활성화가 아닌 미노출).
근거: 기획서 §2, §3-3 발급 권한 정책, AS-001 "권한 정책", "GUI 디테일" PDF 다운로드 버튼 행
상태: 정상

> 접수/확인중 상태에서는 권한 여부와 무관하게 PDF 다운로드 버튼 자체가 존재하지 않는다 — AC-001, AC-002에서 이미 검증됨(중복 정의하지 않음).

### 1.6 PDF 13개 필드 매핑 (WYSIWYG, §5 기준)

#### AC-012 상세 화면 표시값이 그대로 별지 13호 양식 13개 필드에 매핑됨
**Given** 공결 신청 건이 `완료` 상태이고 상세 화면 4개 카드(훈련생/훈련 과정 정보/공결 신청 내역/수기 보완)에 특정 값이 표시되어 있을 때
**When** 유관부서 담당자가 [출석입력요청대장 PDF 다운로드]를 클릭하면
**Then** 추가 조회 없이 화면에 표시된 값이 그대로 별지 13호 양식 ①~⑬ 필드에 인쇄된다(화면에 보이는 값 = PDF에 인쇄되는 값).
근거: 기획서 §3-3 WYSIWYG 원칙, §5 양식 필드 매핑표, §7-3, AS-001 "데이터 필드 ↔ 별지 13 매핑"
상태: 정상 (단, ⑬ 관리자 서명 필드는 §10-9 자산 제공 대기 — 서명 이미지 파일 수령 전까지 TC-013에서 개별 보류 표기, AC-022 참고)

### 1.7 사유(⑨) 표기 규칙 (추가 사유 유무 2케이스)

#### AC-013 추가 사유 없음 — 기본 포맷
**Given** 공결 신청 내역의 추가 사유가 빈 값일 때
**When** PDF가 생성되면
**Then** ⑨ 사유 칸에 `{신청 항목} : {상세 사유}` 포맷으로만 인쇄된다(추가 사유 구분자 `-` 없음).
근거: 기획서 §6 기본 포맷·표기 예시(`공가 : 예비군/민방위훈련`)
상태: 정상

#### AC-014 추가 사유 있음 — 확장 포맷
**Given** 공결 신청 내역에 추가 사유가 입력되어 있을 때
**When** PDF가 생성되면
**Then** ⑨ 사유 칸에 `{신청 항목} : {상세 사유} - {추가 사유}` 포맷으로 인쇄된다.
근거: 기획서 §6 확장 포맷, AS-001 표준 더미 데이터 세트(`공가 : 본인 질병/입원 - 몸살로 병원 진료`)
상태: 정상

### 1.8 15행 구조 · 1행만 채움

#### AC-015 본문 테이블 15행 고정 구조 유지, 1행만 값 채움
**Given** 완료 상태의 공결 신청 1건에 대해 PDF를 생성할 때
**When** PDF가 출력되면

### 1.14 전제조건 대기 (자산 제공 — §10-1·§10-9)

기획서 §10-1·§10-9는 "차단"이 아니라 개발 착수 시 사용자가 자산(훈련기관명 텍스트·서명 이미지 파일)을 직접 제공하기로 확정되어 "전제조건 대기"로 상태가 바뀌었다. 정책 자체는 확정되었으나 실제 자산 값이 아직 없어 값 검증은 자산 수령 후 실행한다.

## 5. 승계된 §10 확인 필요 사항 (AC/TC 대상 외 — 비차단, v1.5 기준)

기획서 v1.5 기준 §10은 총 30건: **정책 차단 6건**(§10-6, 20, 21, 25, 26, 29) / **자산 대기 4건**(§10-1, 9, 18, 19 — 이 중 AC-020·022는 §10-1·9를, AC-018/TC-019는 §10-19를 반영 완료) / **확정 7건**(§10-3, 10, 11, 12, 13, 14, 15 — 본 문서 AC-021·023~027 등에 반영 완료) / **비차단 13건**. 아래 표는 이 13건의 비차단 항목이다. 이번 QA 산출물의 최소 커버 범위에 명시적으로 포함되지 않아 별도 AC/TC를 만들지 않았다. 임의로 결론 내지 않고 기획서 §10 원문 그대로 승계한다.
