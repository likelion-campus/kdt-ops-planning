# POL-CF-02 — 캠프파이어 입장 · 라이브 강의실 입장 정책

## 용어

- **Trainee** = **수강생**
- **Operator** = **강사 또는 매니저** (라이브 강의를 "열" 수 있는 모더레이터 권한자)

## 의도

기존 ClassChat(RocketChat) 환경에서는 **클래스챗 입장(공간 합류)**과 **강의실 입장(라이브 세션)**이
서로 다른 탭의 별도 버튼이었다. 자체 개발 플랫폼 **Campfire는 채팅과 라이브 강의를 한 공간에서 제공**하므로
두 버튼을 분리할 이유가 사라졌다.

본 정책은 이 통합 환경에서 **(1) 누가 Campfire에 입장할 수 있는가(권한·멤버십)**와
**(2) 라이브 강의에 언제 참여할 수 있는가(타이밍)**를 분리해 정의한다.
핵심 원칙: **공간은 통합하되 두 게이트(권한 게이트 / 라이브 타이밍 게이트)는 유지한다.**

## 정책

### 1. 캠프파이어 입장 (멤버십 게이트)

1. **`캠프파이어 입장하기` 버튼은 지원(서류) 합격 상태인 Trainee에게 노출**한다. **별도의 결제 완료 조건은 두지 않는다**(기존 ClassChat 정책 계승).
   - 직전 검토안(v1)에서 "내일배움카드 결제 완료"를 추가 조건으로 두었으나, **결제 완료 상태를 운영상 식별하기 어려워** 본 버전(v2)에서 **지원(서류) 합격 단독** 기준으로 환원한다.
   - "지원 합격"은 기존 "서류 합격"과 동일한 단계를 가리킨다(명칭 통일).
2. **내일배움카드 결제 여부는 버튼 노출과 무관하다.** 결제는 프로그램 진행상 별도로 이뤄지되, Campfire 입장 게이트로 사용하지 않는다.
3. **버튼 노출 시점 = 지원(서류) 합격 확정(발표) 시점**과 동일하게 본다.
4. **합격 철회·자격 상실(수강 포기 등) 시 `캠프파이어 입장하기` 버튼은 노출하지 않는다**(접근 권한 회수).
   이미 입장해 있던 Trainee의 **채팅 데이터·세션은 캠프파이어 내 운영 매니저(Operator)가 직접 처리**한다(자동 회수/삭제 로직은 두지 않음).
5. 결제 유도/안내 UI는 플랫폼에 두지 않는다(결제는 외부 절차로 진행).
6. **노출 위치는 생애주기(지원 합격 → 훈련생 권한 → 수강기간)에 따라 단계별로 다르다.** 진입점은 `수강신청`과 `강의목록` 두 곳이다.

   **(a) `수강신청`(`/my/apply-status`) — 합격 단계**

   | 단계 | 노출 버튼 |
   |---|---|
   | 지원(서류) 합격 | `고용24 수강신청하러 가기` · **`캠프파이어 입장`** |

   - 지원 합격 이후 단계(훈련생 권한 취득·수강기간 포함)에서도 `수강신청` 페이지는 동일하게 `고용24 수강신청하러 가기` + `캠프파이어 입장`을 유지한다.

   **(b) `강의목록`(`/my/courses`) — 훈련생 권한 취득 후**
   `캠프파이어 입장` 버튼은 **훈련생 권한을 받은 이후** `강의목록`에서 노출된다.

   | 시점 | 노출 버튼 |
   |---|---|
   | 수강기간 이전 | **`캠프파이어 입장하기`** · `취업지원 바로가기` |
   | 수강기간 중 | `클래스룸 입장하기` · **`캠프파이어 입장하기`** · `취업지원 바로가기` |

   - `클래스룸 입장하기`(LMS)는 **수강기간 중에만** 노출된다(기존 "교육 진행중" 카드와 동일).
   - `캠프파이어 입장하기`는 기존 `클래스챗 입장하기` 자리를 대체한다.
7. **`캠프파이어 입장(하기)`으로 입장하면 캠프파이어의 맨 상단 채널로 진입**한다(수강신청·강의목록 어느 위치에서 눌러도 동일).
8. 입장 후 Trainee는 **라이브 진행 여부와 무관하게 Campfire(채팅 공간)에 상시 출입**할 수 있다.
9. **적용 범위 = 본 정책 적용 이후 신규로 개설되는 부트캠프(신규 기수)에 한한다**(버튼 통합·라이브 흡수 등 구조 변경 기준).

### 2. 라이브 강의실 입장 (타이밍 게이트)

1. **`강의실 입장` 버튼은 항상 활성** 상태로 노출한다. 별도의 활성/비활성 조건을 걸지 않는다.
2. **수강생(Trainee)은 강의가 열려 있을 때만** 실제로 강의실에 입장할 수 있다.
   강의가 열려 있지 않을 때 입장을 시도하면 안내 문구를 노출한다 —
   **"강사가 강의를 열지 않으면 모더레이터가 강의를 연 이후에 참여할 수 있습니다."**
3. **강의 열기는 강사·매니저(모더레이터 권한)만 수행**할 수 있는 기능이다.
4. **Operator의 Campfire 입장과 라이브 시작은 분리**한다. Operator가 Campfire(채팅)에 들어온 것만으로는
   라이브가 시작되지 않으며, 강의는 **명시적 "강의 열기" 액션**으로만 시작된다(채팅 목적 입장 시 라이브 시작 오알림 방지).
5. Trainee는 Campfire 내에서 **현재 강의 진행 여부(ON/OFF)를 확인**할 수 있다.

## 버튼 노출 매트릭스 (한눈에)

### A. 생애주기 × 페이지별 CTA (수강생 기준)

진하게(**굵게**) 표시된 버튼이 Campfire 진입점이다.

| 생애주기 단계 | `수강신청` (`/my/apply-status`) | `강의목록` (`/my/courses`) |
|---|---|---|
| ① 지원(서류) 합격 | `고용24 수강신청하러 가기` · **`캠프파이어 입장`** | — (훈련생 권한 부여 전) |
| ② 훈련생 권한 · 수강기간 이전 | `고용24 수강신청하러 가기` · **`캠프파이어 입장`** | **`캠프파이어 입장하기`** · `취업지원 바로가기` |
| ③ 수강기간 중 | `고용24 수강신청하러 가기` · **`캠프파이어 입장`** | `클래스룸 입장하기` · **`캠프파이어 입장하기`** · `취업지원 바로가기` |
| ④ 합격 철회·자격 상실 | `고용24 수강신청하러 가기` (**`캠프파이어 입장`** 회수) | **`캠프파이어 입장하기`** 회수 |

### B. 캠프파이어 내부 — 라이브 영역 CTA (역할 × 라이브 상태)

| | 라이브 **OFF** | 라이브 **ON** |
|---|---|---|
| **수강생** (Trainee) | `강의실 입장` (항상 활성 · 클릭 시 안내 문구) | `강의실 입장` (참여) |
| **강사·매니저** (Operator) | `강의 열기` | `강의 종료` |

> 보조 표기: `고용24 수강신청하러 가기`·`취업지원 바로가기`·`클래스룸 입장하기`는 본 정책 범위 밖(외부/타 도메인) 버튼으로, 노출 맥락 참고용으로만 표기.

## 예외 처리

각 예외는 **[유저 영향]**과 **[해결안]**을 함께 정의한다.

| 케이스 | 유저 영향 | 해결안 |
|---|---|---|
| 지원 합격 발표 직후 버튼 미반영 (합격 확정 시점과 노출 시점 불일치) | "합격했는데 입장 안 됨" CS | 버튼 노출을 **합격 확정 이벤트**에 묶어 시점 일치 보장 |
| 합격 철회·자격 상실 후 재진입 시도 | 권한 없는 공간 노출 | 버튼 미노출로 회수. 이미 입장 중이던 경우의 채팅 데이터·세션은 **운영 매니저가 직접 처리**(`§1-4`) |
| 합격 취소·철회 | 권한 충돌 | 합격 미충족이면 **버튼 미노출**(권한 게이트) |
| 강의 미오픈 시 수강생이 `강의실 입장` 클릭 | "왜 안 들어가지" 혼란 | 항상 활성 버튼 + 클릭 시 안내 문구 노출(§2-2) |
| 맨 상단 채널 미존재/로딩 실패 | 빈 화면 진입 | 기본 채널 보장 + 로딩/Empty State 처리 |
| `캠프파이어 입장하기` / `강의실 입장` 중복 클릭 | 중복 요청·오류 | 클릭 직후 로딩 처리로 다중 요청 차단 |
| 합격 데이터 적재 지연(분석 로그) | 운영 지표 왜곡 | 권한 판정은 합격 원장 기준, 분석 로그와 분리 |

## 비정책 (의도적으로 정하지 않음 / 확인 필요)

- ~~기존 ClassChat 입장자 소급 적용 여부~~ → **확정**: 신규 부트캠프(신규 기수)부터만 적용, 소급 없음(`§1-9`).
- ~~캠프파이어 입장에 "내일배움카드 결제 완료" 조건 추가~~ → **철회(v2)**: 결제 완료 상태 식별이 어려워 **지원(서류) 합격 단독** 기준으로 환원(`§1-1`).
- 자격 상실 시 채팅 데이터·세션은 운영 매니저가 직접 처리, 자동 로직 없음(`§1-4`).
- 강의실 입장 버튼의 활성/비활성 조건은 두지 않는다(항상 활성).
